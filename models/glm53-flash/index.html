02 / KERNEL BREAKDOWN

四个阶段，各自在做什么？

Zeus · 16 rank / 32 core

下列介绍对应本轮 Zeus 实现。Router 产生路由，Routed 与 Shared 形成专家输出，Reduce 完成本地加权归并；跨卡通信不计入这些窗口。

01 · 路由选择

Router

对输入做路由投影、评分和带 bias 的 Top-K 选择，为每个 token 产生 8 个 routed 专家 ID 与路由权重。

关注：投影、评分与 Top-K 的周期增长。
02 · 稀疏专家

Routed

按真实路由执行专家 Gate / Up、激活与 Down。本轮采用 per-tensor FP8，使用 M1 / M2 / M4 token 合并。

关注：活跃专家数、权重复用、窗口与尾部调度。
03 · 共享专家

Shared

对全部 token 执行共享专家 FFN。本轮 Zeus 采用 BF16，仅在 EP0 上执行，并在其中按 TP4 分片。

关注：固定专家权重下，计算和数据搬运如何随 batch 增长。
04 · 本地归并

Reduce

读取有效的本地 routed 输出，应用路由权重并求和，在持有 Shared 的分支合入共享输出。

关注：有效行读取与加权求和；不含跨卡 AllReduce。

各阶段维持统一 JIT 入口；batch 维度是编译期常量，窗口和尾部可在 kernel 内特化。M 合并大小与窗口宽度是两个概念。

纵轴是平均每层微秒数：各阶段逐层独立取最大 rank，累加 42 层后取 49 点平均，再除以 42。各阶段的最慢 rank 可能不同，不能把它们相加当成完整 MoE 时间。

纵轴 = 当前 batch 的阶段平均 cycles ÷ BS16 的阶段平均 cycles；虚线 = 总 batch ÷ 16。曲线低于虚线，表示相对 BS16 的增长小于线性。

纵轴 = 周期增长倍数 ÷ batch 增长倍数。低于 1 表示每 token 的周期成本下降；高于 1 表示上升。参考线 1 对应 BS16 的单 token 成本。

03 / SAMPLING

49 个点是怎样组成的？

896条不同请求
→
7 × 128批次 × 每批请求数
→
7个固定 decode 位置
→
49个采样点 / batch 档位
一个采样点
一批请求在一个 decode 位置的真实逐层输入，例如 train00 / step017；每个点均重放全部 42 层 MoE。不是 49 批请求，也不是连续执行 49 个 step。
保留的 decode 位置
017、033、049、065、081、097、113。索引从第一个 decode forward 的 0 开始；step001 已从双方全部 batch 和数据划分中排除。
batch 如何对齐
总 BS16–128，间隔 8，共 15 档。每层 BS16 取该层 BS128 父输入的前 16 行，BS32 取前 32 行；H200 与 Zeus 用 hidden hash 核对。每层独立重放，不宣称运行过相应小 batch 的整模轨迹。
统计与选择
同一 batch 的 49 个点按总 token / 总时间汇总。train 3 批、validation 2 批、test 2 批；只用 train 选择 batch，随后报告 holdout。同一请求的多个 step 存在关联，不视作 49 个独立同分布样本。

04 / MEASUREMENT & VALIDATION

测量边界与验证记录

Zeus TP4 × EP4

4 card / 16 rank / 32 core，400 MHz。每个 launch 取最慢 core，rank 内累加阶段，逐层取最慢 rank，最后累加 42 层。

tokens/s/card = 总 BS × 400,000,000 ÷ cycles ÷ 4

H200 MoE TP1 × EP4

4 张 H200 NVL，每卡 72 个完整 Routed 专家；独立 FP8 Shared 跨四卡 TP4。各层先取每轮重复均值，再取轮次中位数，取最慢 EP 后累加 42 层。

tokens/s/card = 总 BS × 1,000 ÷ ms ÷ 4

激活采集拓扑为 TP4/EP1，与执行拓扑分开记录。当前 Zeus 统计纳入 493,920 个时序 case；H200 保留 2,940 个 rank case / 123,480 个层卡点。本轮没有 VCS/RTL 或整模型性能结论。
