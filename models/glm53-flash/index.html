02 / KERNEL BREAKDOWN

四个阶段，各自在做什么？

Zeus · 16 rank / 32 core

下列介绍对应本轮 Zeus 实现。Router 产生路由，Routed 与 Shared 形成专家输出，Reduce 完成本地加权归并；跨卡通信不计入这些窗口。

01 · 路由选择

Router

每个 rank 只处理自己的本地 token，采用 calibrated sigmoid 与带 bias 的 Top-K，产生 8 个专家 ID 和路由权重，再进行一次 raw-word gather。

关注：本地 1–8 行特化、投影、评分与 Top-K 的周期增长。
02 · 稀疏专家

Routed

按真实路由执行专家 Gate / Up、激活与 Down。本轮采用 per-tensor FP8，使用 M1 / M2 / M4 token 合并。

关注：活跃专家数、权重复用、窗口与尾部调度。
03 · 共享专家

Shared

对全部 token 执行共享专家 FFN。本轮 Zeus 采用 BF16，仅在 EP0 上执行，并在其中按 TP4 分片。

关注：固定专家权重下，计算和数据搬运如何随 batch 增长。
04 · 本地归并

Reduce

读取有效的本地 routed 输出，应用路由权重并求和，在持有 Shared 的分支合入共享输出。

关注：有效行读取与加权求和；不含跨卡 AllReduce。

BS16–128 的各阶段维持统一 JIT 入口；gather 后 Shared / Routed / Reduce 都直接读取 rank blocks。batch 维度是编译期常量，窗口和尾部在 kernel 内特化。M 合并大小与窗口宽度是两个概念。

口径：总 BS × 400,000,000 ÷ 该阶段 42 层平均 cycles ÷ 4。各层先取该阶段最慢 rank（Router 取最慢 owner），累加 42 层，再对 49 个采样点取平均时间。分子只计模型输入 token，不乘 Top-K 或层数；Shared 也按四卡归一化。

曲线走平表示增加 batch 后该阶段的单位卡处理速率不再明显提高；向下表示时间增长超过 token 数增长。默认隐藏吞吐数量级较大的 Router，可勾选或点「只看」检查；交互图默认放大纵轴范围，突出变化趋势；可勾选「纵轴从 0 开始」比较绝对比例。下载图保留从零开始的完整四条曲线。

纵轴是平均每层微秒数：各阶段逐层独立取最大 rank，累加 42 层后取 49 点平均，再除以 42。各阶段的最慢 rank 可能不同，不能把它们相加当成完整 MoE 时间。

纵轴 = 当前 batch 的阶段平均 cycles ÷ BS16 的阶段平均 cycles；虚线 = 总 batch ÷ 16。曲线低于虚线，表示相对 BS16 的增长小于线性。

纵轴 = 周期增长倍数 ÷ batch 增长倍数。低于 1 表示每 token 的周期成本下降；高于 1 表示上升。参考线 1 对应 BS16 的单 token 成本。

03 / SAMPLING

49 个点是怎样组成的？

896条不同请求
→
7 × 128批次 × 每批请求数
→
7个固定 decode 位置
→
49个采样点 / batch 档位
一个采样点
一批请求在一个 decode 位置的真实逐层输入，例如 train00 / step017；每个点均重放全部 42 层 MoE。不是 49 批请求，也不是连续执行 49 个 step。
保留的 decode 位置
017、033、049、065、081、097、113。索引从第一个 decode forward 的 0 开始；step001 已从双方全部 batch 和数据划分中排除。
batch 如何对齐
总 BS16–128，间隔 8，共 15 档。每层 BS16 取该层 BS128 父输入的前 16 行，BS32 取前 32 行；H200 与 Zeus 用 hidden hash 核对。每层独立重放，不宣称运行过相应小 batch 的整模轨迹。
统计与选择
同一 batch 的 49 个点按总 token / 总时间汇总。train 3 批、validation 2 批、test 2 批；只用 train 选择 batch，随后报告 holdout。同一请求的多个 step 存在关联，不视作 49 个独立同分布样本。

04 / MEASUREMENT & VALIDATION

测量边界与验证记录

Zeus TP4 × EP4

4 card / 16 rank / 32 core，400 MHz。每个 launch 取最慢 core；每层先取最慢本地 Router，再加最慢 rank 的 Shared + Routed + Reduce，最后累加 42 层。gather 依赖作为阶段边界，真实通信耗时未计入。

cycles = Σ层 [max_owner(Router) + max_rank(Shared + Routed + Reduce)]
tokens/s/card = 总 BS × 400,000,000 ÷ cycles ÷ 4

H200 MoE TP1 × EP4

4 张 H200 NVL，每卡 72 个完整 Routed 专家；独立 FP8 Shared 跨四卡 TP4。各层先取每轮重复均值，再取轮次中位数，取最慢 EP 后累加 42 层。

tokens/s/card = 总 BS × 1,000 ÷ ms ÷ 4

激活采集拓扑为 TP4/EP1，与执行拓扑分开记录。当前 Zeus 统计纳入 493,920 个时序 case；H200 保留 2,940 个 rank case / 123,480 个层卡点。Zeus 使用捕获的 H1 输出和 CPU collective double，不计 H1、真实通信、host/JIT，也没有新增 VCS/RTL 或整模型性能结论。

查看时序资格、数值验证与解析误差

本轮 49 个 decode step 采样点共 493,920 个时序 case、672 个 shard 全部完成，并行上限 192 workers，宿主耗时 2.95 小时，最终有效矩阵零失败。全量唯一覆盖、输入/权重与资格 hash 审计通过；H200 沿用同输入的原测量。

独立数值资格：384 项 MoE 回归通过；train00/step017、全部 15 档、layer/rank (3,0)/(5,15)/(44,4) 的 45 项完整模式通过实现参考、完整/本地 Router 逐位比较、Reduce exact 和 changed-input Graph；45 对完整/时序模式的逐 launch/core cycles、输入/权重、Router 结果与语义 zbin 一致。

当前完整模式中有 18 项解析 SiLU 数学预算超限：layer5/rank15 的 BS112/120/128；layer44/rank4 的 BS16/24/32/40/48/56/64/72/80/88/96/104/112/120/128。原阈值不变，单列诊断，不与实现参考或 Graph 门禁混淆。

时序模式保持真实 Router，仅省略已资格 Routed/Shared 的 PE 数值乘加；时序输出及下游 Reduce 不计为数值 PASS，493,920 个时序 case 不代表全矩阵数值验收。

测量源码 508bb2b7526e；整理后的 PR head 508bb2b7526e 与其保留代码、测试及 benchmark 脚本逐文件一致。PR head 的 CI 已结束：failure（发布时快照，实时状态见 GitHub），旧 SHA 的 CI 不继承为新 SHA 的 PASS。

73 个失败均在 Routed 编译阶段：2026-11-05 daily 包内编译器不支持 --enable-l2-stage-packing 与 --l2-stage-packing-preserve-prefix。本次独立测评使用支持这两个参数的 master 编译器 27e77de18，结果与 CI 分开记录。

基础设施重试记录：共 2 次执行，初次因磁盘空间波动触发保护及临时 JIT 文件写入失败，48 个未完成 shard 在相同冻结环境下补测。旧尝试保留；最终矩阵按唯一 case 去重，全量覆盖未删减。宿主耗时包含恢复过程。
