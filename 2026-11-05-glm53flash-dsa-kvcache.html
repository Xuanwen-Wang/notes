01 / ONE ATTENTION LAYER

三段计算，两次核心通信。

DSA 在主 Attention 前增加了一个轻量 Indexer。它先给历史组打分，主 Attention 随后只读取选中的 token。MLA 的 latent 压缩和 DSA 的历史选择，分别减少每个 token 的缓存宽度和本次读取的历史数量。

当前观察 CP0：4096 个完整历史组，选中128组，共512个 token；普通驻留512行路径。

均衡模式取一份均衡选择示意；集中模式优先使用 CP0 实际拥有的组，再向其他 CP 分配。它们只用于理解计算规模，不代表模型相关性或测得的负载分布。

P1生成当前表示，检索历史。sgl_dsa_proj_indexer_topk1 · 四条逻辑支路融合为一次计算 launch

先把“当前 token 的固定维度投影”和“随历史增长的扫描”分开。它们融合在同一个 kernel，下面的顺序表达数据依赖，实际可能交错或重叠。

  1. 从 hidden state 得到 Q 的压缩表示

    [4,4096] × [4096,1536] → [4,1536]

    RMSNorm 保持 shape。这个1536维表示供主 Query 与 Indexer Query 两条支路使用。

  2. 主 Query：先展开 heads，再吸收 K 投影

    [4,1536] → [4,64,256] → [4,64,512]（完整逻辑）

    每个 CP 只分工生成16个主 heads，每 core 8个。K absorption 按 head 将256维 Query 变成512维 latent Query，让后续直接与历史 latent 点积。

    本 CP 输出 BF16 [4,16,512] · 每 core [4,8,512]
    qhT(WK,hc) = (WK,hTqh)Tc

  3. 写入当前 token 的共享 KV latent CACHE WRITE

    [4,4096] × [4096,512] → RMSNorm → c [4,512]

    每层、每 token 一份512维 c，由64个主 heads 共用。 量化为512个 FP8 值和4个 FP32 scales，物理每行528 bytes。对应 CP 的有效 writer 追加到 GDG pool，旧历史不重算。

  4. 准备 Indexer Query 与 head 权重

    [4,1536] × [1536,4096] → reshape [4,32,128]

    另一套专用投影生成32个128维检索 heads，随后进行 Hadamard 旋转与 FP8 量化。另从 X 投影出 [4,32] head 权重，用于合并打分。每个 CP 都需要完整32个 Indexer heads。

  5. 把四个检索 keys 汇成一个 pooled key INDEXER WRITE

    X 经独立投影生成128维 Indexer key 和128维 pooling gate。当前值与该请求的 tail 结合，每凑齐四个 token，沿 token 轴做逐特征的加权汇聚。

    4 × [128]keys + gates + 位置偏置
    →
    1 × [128]一条 pooled key

    128维宽度不变，历史条数约为 S/4。不是简单平均，也不把主 Attention 的四条512维 latent 合并。旋转、量化后的 pooled-key body 进入 LDG；未满组留在 tail。

  6. 扫描本 CP 的 pooled-key 历史 INDEXER READ

    [32,128] × [128,4096] → [32,4096]

    每个 query head 对每个历史组打分，再经 ReLU、head 加权、scale 调整和 head 归约，变成每组一个分数。这里的历史组数随 S 增长。

    典型 tile：[32,128] × [128,1024] → [32,1024] → [1024]

    1024表示一次处理1024条 pooled keys，代表4096个原始 token。两个 core 按 LDG 页归属分摊扫描；它与存储 page size 是两个概念。

  7. 做局部筛选，打包通信数据

    候选路径每请求、每 CP 保留最多512个组的 FP32 分数和 global group IDs（当前 IDs 以 FP32 精确整数保存）。部分长度改用 raw-score 传输，交给 P2 筛选。与本 CP 的16个主 Query heads 一起写入固定 payload。

第一次 AllGather QUERY + SELECTION

一次打包传输，完成两件事：凑齐主 Query 的 heads，以及让全局选择看到四个 CP 的分数信息。

主 Query · BF16每 CP [4,16,512] → 每 rank 获得 [4,64,512]
候选 / raw scores四份本地组分数或候选；候选路径最多4×512组

pooled-key 历史、主 latent 历史、Indexer Query 留在本地。通信使用 BF16 view 作为字节 carrier，FP32 分数/IDs 不因此转成 BF16 数值。

P2只取选中的历史，做 Attention。sgl_dsa_topk2_gather_attn · TopK2 → Gather → QK → Softmax → PV

  1. 全局选出最多512个四 token 组

    合并四个 CP 的候选或 raw scores，确定全局选择，再筛出本 CP 拥有的组。512是四个 CP 合计的组数，每个 CP 的数量由真实选择分布决定。

    CP0：选中128组 × 4 + tail 0 = 512个 token

    尾部未满四个 token 的部分另外补入。最坏可有一个 CP 拥有几乎全部选中组，因此本地 Attention 不一定只算512个 token。

  2. 组 ID → 物理 slot → Gather latent KV READ

    通过 CP 归属、slot/page 表找到四 token 组的物理位置，从本 CP 的 GDG latent pool 读出 body 和 scales，准备本 core 的 LDG K/PV 工作区。

    选中的主 latent Cᵣ：[512,512]

    此处读取512维主 latent；128维 pooled key 已经完成检索工作。Gather、类型/scale 处理、DT 与 LW 是真实计算前的数据准备。量化 scale 可以融入 UScale 或 PV 概率，不要求完整物化反量化矩阵。

  3. QK：每个主 head 对选中的 token 打分

    [64,512] × [512,512] → scores [64,512]

    数学 M 是主 heads，K 是512维 latent 特征，N 是本地 token 数。当前实现再乘1/16（来自原 QK head_dim=256）并 mask 无效填充。

  4. 本地 Softmax：沿 token 轴归一化

    scores [64,512] → probabilities [64,512]；LSE [64]

    每个 head 独立归一化。保留 log-sum-exp，作为之后正确归并四个 CP 的依据。流式路径会在线更新 max、sum 和输出。

  5. PV：对历史 latent 加权求和

    [64,512] × [512,512] → Oᵣ [64,512]

    同一份 latent 在 QK 中充当 K，在 PV 中充当 V。实现将512维输出拆成四个128维块，V up-projection 留到 P3。

    每块：[64,512] × [512,128] → [64,128]，共四块

  6. 写出本地输出和归一化统计

    BF16 Oᵣ [4,64,512] + FP32 LSEᵣ [4,64]

    空 shard 约定 O=0、LSE=−∞。因为各 CP 在各自历史子集上归一化，四份 O 不能直接相加或平均。

两个 core 怎么分？

普通 R=4：core0 处理请求行0/2，core1处理1/3；每个请求计算完整64个 heads。

实际用哪个计算块？

当前 CP0 有512个有效 token，普通驻留路径使用512行。有效长度与 padding 后的计算 tile 不相同。

普通驻留路径按有效 token 数选256、512、640行；超过640行时按256行流式计算。部分合格配置另有640行预取调度。小块可显式转置后读取普通 weight，源码也保留 vcache 分支；实际 mode 要核对动态指令。

第二次 AllGather PARTIAL O + LSE

收集四个 CP 的局部结果和 Softmax 统计，供 P3 归并。

局部 Attention 输出BF16 [4 CP,4 tokens,64 heads,512]
log-sum-expFP32 [4 CP,4 tokens,64 heads]

这里传的是结果和统计，不需要把各 CP 的历史 KVCache 集中到一起。

P3归并 partials，回到 hidden space。sgl_dsa_absorb_proj · LSE merge → V absorb → O projection

  1. 按 LSE 正确归并四份局部结果

    LSE 记录每个 head 在该 CP 上的归一化分母。分数高的历史子集应在最终结果中获得更大的权重。按一个 token/head，非空侧的数学公式是：

    m = maxᵣ LSEᵣ
    wᵣ = exp(LSEᵣ − m)
    O = Σᵣ(wᵣ · Oᵣ) / Σᵣ wᵣ

    实现以 FP32 算术合并，并处理空侧和数值边界。逻辑上得到完整的512维 latent 结果；真正执行时，只做本 CP 输出区所需的 token 行。

  2. V absorb：每个 head 从512维回到256维

    每 head：[1,512] × W_VC,h [512,256] → [1,256][4,64,512] → [4,64,256] → flatten [4,16384]

    两个 core 各负责32个 heads 的投影片段。写出 BF16 中间结果并同步后，O projection 可读取完整输入。

  3. O projection：从16384维回到4096维

    [4,16384] × [16384,4096] → [4,4096]（完整逻辑）

    V/O 权重使用 BF16 LDG pack，FP32 累加后输出 BF16。这里不再读取历史 KV，LDG 流量主要来自模型投影权重。

  4. 按“平坦输出的四分之一”分工

    本 rank carrier：[4,1024] = 4096个元素 → 完整 token [1,4096]

    每 rank 负责 flatten([R,4096]) 中一段连续四分之一，不应一律理解成“每个 token 的1024维”。R=4 时各 CP 拥有一个完整 token；R=1 时各 CP 拥有同一 token 的1024维片段。

当前示意：直接交给本地 mHC

B=R=4、mHC 按 token 分片，输出可解释为 [1,4096]，省去第三次输出 AllGather。

输出与 mHC 分片匹配

当 mHC token_sharded、B=R 且 R 可被4整除，本 rank 直接返回 [R/4,4096]。R=4 的部分合格配置还可融合 P3 与后续 mHC Post/Pre。

不满足直接交接条件

执行第三次 CP4 AllGather，将四份 R×1024 元素拼成完整 [R,4096]。R=1/2/6 或其他不匹配场景走这条交接路径。

06 / TWO HISTORIES

每条多宽，和一共多少条。

这两个方向最容易混淆：128/512是固定特征宽度；G/S 是随历史增长的条数。两套 cache 都由各层各自维护。

Indexer K 历史

128 维 / 每4个token

帮助判断“看哪些组”。FP8 body 分布在两个 core 的 LDG banks，另有 scale、有效性和页映射。

全请求逻辑 [16384,128]
当前 CP0 [4096,128]

P1 写，P1 扫描。 所有32个 Indexer heads 共用这套 keys。

主 latent 历史

512 维 / 每token

用于真正的 Attention。当前默认入口采用 CP-local GDG pool，每行512 bytes body + 16 bytes scales。

全请求逻辑 [65536,512]
物理每token 528 bytes

P1 追加，P2 选读。 64个主 heads 共用每个 token 的一份 latent。

另有一个数字：Top512 groups。它表示最多选择512个四 token 组，与 latent_dim=512 的含义完全独立。

LDG 历史128维 pooled-key body长期保存；P1 更新与扫描
GDG 历史512维 latent + scales长期保存；P1 写入、P2 选读

07 / READING THE VIEWER

先找业务段，再解释利用率。

按下面五个窗口定位，能把“传了什么、谁在等、哪种 shape”联系起来。页面上的计算规模不等于已经测出的时间或带宽。

窗口重点观察需要分清
P1 当前 token 投影Q/KV/Indexer 投影与 K absorb固定模型维度与 batch 行数
P1 历史扫描反复出现的 Indexer PE，典型 M/K/N=32/128/1024有效历史、tile、两核的 LDG 页归属
P2 数据准备GDG Gather → scale/类型处理 → DT/LW → QKGDG 读取、LDG 写入、WL1 供数是不同通路
P2 AttentionQK → Softmax → 四块 PV；流式路径按256行重复M=64或32、有效 n_r 与 padding 后 tile
P3 输出LSE merge、V/O PE、rank 内同步与输出交接模型权重流量，以及是否存在第三次 AllGather

单元 busy、有效字节除以 PE 时间、MC 实际返回带宽是不同指标。核对匹配的二进制与输入、core、动态 M/K/N、DF、minitile、mask、UScale 和 trace 来源，再讨论瓶颈。

时间与带宽需要真实 trace 支持；小页管理不自动等于小 PE，decode 单 token 也不自动等于 M=1。
