TritonShared - 模型部署性能优化的三个层次

一个算子从全模型到单 core 跑到最快，穿过三层、各归一个系统：A 分布式部署（推理框架）定「算多大」、B dispatch（torch zeus）搜「怎么切块 + 哪种 weight layout」、C 编译优化（Compiler）定「单 core 怎么算到最快」。C 的灵魂是 overlap——让 PE 永不空泡，访存藏进计算。

为什么 overlap 是 C 层的灵魂　— double buffer / ping-pong

同样的 LD / PE / ST 工作量，串行让 PE 大量空泡（墙钟 = Σ 各段）；两块 buffer 交替错位流水，把访存藏进计算（墙钟 ≈ max 单元时长）。

实现：double buffer 提供两块可交替 buffer；InjectSyncPass 用 mailbox 把生产/消费连成异步流水；循环 Phase 4 bootstrap 预充把流水「点着」。该往哪边 overlap、buffer 要多深由计算访存比决定——藏不住的暴露项（DRAM 权重税 / 激活暴露 / 写回反压）就是优化目标。
