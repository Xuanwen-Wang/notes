ISSUE #153 · STRUCTUREDTOMEMREF · 4 行 × 128 BF16

四行 Gather，究竟删掉了什么？

本来只需要“读 flag → 判断 → 搬这一行”，编译器却先把判断结果写进临时内存，随后又读回来判断。去掉这圈内存往返，再去掉行循环的重复控制，kernel 少了 409 cycles。

1857 → 1448 cy同参 VCS 实测 · 减少 22.02%
少 112 个 CT 事件减少控制工作，不是减少数据量
仍搬 4 × 256 B四条 LD 还没有实现并行连发
主图：删掉的工作省多少 cycles对应代码验证与原始时序

一张图看懂：每一行从 flag 到 LD，原来绕了什么路

①～④ 对应四条数据行 load。 flag 决定这一行要不要搬，ids 决定从源矩阵的哪一行搬。下面把 CT（控制核）做的工作写在色块里，红色是多余步骤，黄色才是搬数据的 LD。

if flags[r] != 0: result[r, :] = src[ids[r], :]

这是这一行的核心语义。所有示意都保留 mask 判断；源行号 ids[r] 仍是运行时值。

Before：先为四行生成临时 mask，再逐行读回并搬运下面两阶段按先后执行

额外循环控制：阶段 A 和 B 各有一个行循环，每轮都要判断 r < 4、计算动态行偏移、r++、跳回循环头。

读第①行：Before “flag → 比较 → 存 mask_tmp → 读 mask_tmp → 再判断”；After “flag → 直接判断”。少的是中间绕路，这一行的数据仍要搬。

删掉的第一类工作：布尔值的内存往返

判断结果原本已经在 CT 中，却被变成 0/1，写入 L2 的 mask_tmp，之后读回再判断。After 直接用原始 flag，不再需要临时 mask buffer 和生成它的循环。

删掉的第二类工作：循环控制和动态行偏移

行数编译时已知，展开成四份代码后，r < 4、r++、回跳及部分 base + r × 4 寻址可以消除。ids[r] × K 仍需运行时计算。

用一句话对应参考图：参考例子把“四次等待”重叠起来；本次把“生成临时 mask 再读回”和“重复循环控制”删掉。优化机制不同，所以这里用删除的工作解释收益。

为什么第一条 LD 能提前？ CT 少走了生成 mask 的循环，以及第一行的部分控制路径，后面的清零配置、地址准备和 LD 可以更早推进。首行 LD 从 kernel 起点后的 898 cy 提前到 514 cy，这是结果证据，不是“898 cy 全是阻塞”。

第二步少掉的 72 个 CT 事件：3 个临时 mask descriptor 配置 + 29 个循环控制 + 40 个四行 mask 生成主体事件。它们对应路径中的实际指令，不能把 72 当作 72 cycles。

仅展开版本中，mask 循环的 69 个事件跨越约 240 cycles；消除这条路径的 kernel 净收益为 320 cycles，包含后续执行和等待变化。此处没有逐条指令的独立延迟归因。

验证与边界：需要深入时再展开

四条 LD 现在能并行发了吗？还没有，这也是剩余优化方向。

目标四行互不重叠，重复源行也只是重复读取。从这个最小 kernel 的数据语义看，存在重叠执行的空间。但验收汇编仍有 LD_MAIL → CT_MAIL 等待链，下一行的地址准备受到前面 LD 的制约。

当前仍近似：发 LD① → 等 LD → 准备②的地址 → 发 LD② → …
期望研究：  发 LD① → 在搬①时准备②的地址 → 尽早发 LD② → …

修复后 LD 启动间隔约 223 cy，而自身执行约 113 cy。尚未追清每条依赖来自 alias、descriptor 保护还是控制流规划，不能直接删 mail，也不能把间隔都算作可消除的等待。

查看原始 VCS 时序：确认搬运更早开始，而不是搬运变快了

旧图里的“开始前已过 696 cy”指的是：清零指令在 kernel 启动后第 696 cy 才开始，第 779 cy 结束，自身只执行 83 cy。此前还有元数据加载、mask 生成等工作；696 不是清零的等待耗时，也不是本次省下的 cycles。

“静态小行数、非末维、连续 payload、单用途 mask”到底限制了什么？
  • 静态小行数：编译时知道要取 4 行；具体取哪行仍由运行时 ids 决定。默认 gather-unroll-limit=16，超过阈值保留循环，0 关闭。16 是策略，不是全局最优证明。
  • 非末维、末维连续：在 [行, 列] 的行维选择数据，一行内元素连续，末维 stride=1 且长度大于 1。
  • 单用途、纯 pointwise mask：每行判断只依赖对应行输入；只接受满足检查的整数比较/布尔运算，不能任意重算共享或有副作用的计算。
  • 动态/大行数、1D/末维 gather、singleton、非连续 payload、scatter 保留原路径；共享或不满足检查的 mask 保留物化。用户外循环不展开。
  • 保留 mask 保护、独立输出分配和填零，不把输入当 scratch。只克隆并删除新生成的 gather loop，不删除仍有消费者的上游 producer。
