02 / Before 有两个循环，After 直接让 flag 控制每一行

BEFORE · 两个循环

先生成 mask，再读回来

flags→比较 → 0/1→mask_tmp 写入 / 回读→分支 + LD
ids, flags = load_metadata()

# C1：生成临时谓词的 CT 指令组
mask_tmp = alloc(4 × int32)
for r in range(4):
    mask_tmp[r] = int(flags[r] != 0)

result = alloc(4, 128)
fill_zero(result)                  # F0

# C2：循环控制 / 行偏移 / 读回谓词
for r in range(4):
    valid = mask_tmp[r] != 0
    if valid:
        # C3 算地址和配置；G0～G3 搬数据
        load_row(src + ids[r] * K,
                 result + r * 128) # G[r]
store(result)                     # S0

真实 IR 中，谓词以 i32 存储，4 行分配 16 bytes。每次循环还要比较边界、递增、回跳和计算动态访问偏移。

AFTER · 展开 + 标量谓词

读 flag，直接分支

flags[常量行号]→与 0 比较→分支 + LD
ids, flags = load_metadata()
result = alloc(4, 128)
fill_zero(result)                  # F0

if flags[0] != 0:
    load_row(src + ids[0] * K, result + 0)   # G0
if flags[1] != 0:
    load_row(src + ids[1] * K, result + 128) # G1
if flags[2] != 0:
    load_row(src + ids[2] * K, result + 256) # G2
if flags[3] != 0:
    load_row(src + ids[3] * K, result + 384) # G3

store(result)                     # S0

不再生成 mask_tmp，行索引成为常量。源地址 ids[r] * K 仍需要运行时计算，无效行的 guard 与结果填零仍保留。

“单用途、纯 pointwise”是什么意思？ mask 没有其他需要保留其结果的消费者；每一行的布尔计算只依赖对应行输入，不做归约、不读写外部状态。本 MR 只接受满足检查的整数比较和布尔运算，不把任意 tensor 计算都重算一遍。

04 / 先认指令，再看同一条指令前后怎么变

F0 清零 → G0 / G1 / G2 / G3 搬四行 → S0 写回结果。 下面的 ID 在代码、时序图和解释中保持一致，表示对应的动态指令实例，不是汇编 PC。CT 控制代码用 C1～C3 标注为指令组，避免和单条搬运指令混淆。

F0VP_STSR · 结果清零

给 result 的 4 × 128 个 BF16 填 0，保证被 mask 掉的行和列仍为 0。图里原来的紫色“83”就是它执行了 83 cy。

G0–G3LD_MOV · 分别搬四行

G0：src[ids[0]] → result[0]；G1、G2、G3 同理。每条搬 256 B，黄色块代表实际执行，左边的路程代表开始前已过去的时间。

S0ST_MOV · 结果写回

把 L2 中的 result 写到输出内存。蓝色块前后均为 116 cy；它提前完成，是因为前面的工作更早完成。

BEFORE · 读懂代码顺序（非等比例）
  1. C1 CT 循环读 flags，生成 0/1，写 mask_tmp。
  2. F0 配置并启动 result 清零。
  3. C2 CT 用 r 判断循环、算偏移、读 mask_tmp。
  4. C3 有效行读 ids[r]、算源地址、配置 descriptor → G0。
  5. 重复 C2 / C3，启动 G1 → G2 → G3，最后 S0 写回。
AFTER · 对应代码顺序（非等比例）
  1. C1 生成 mask_tmp 的整个循环：删除。
  2. F0 可更早配置、启动清零。
  3. C2 的循环控制和动态行偏移：删除或常量折叠；直接读 flags[0] 判断。
  4. C3 仍需读 ids[0]、算源地址、配置 descriptor → G0。
  5. 用常量行号直接处理 G1 → G2 → G3，最后 S0 写回。

这张图与“DMA 批量化”的例子不同： 本次四行 LD 没有同时连发。先保留真实先后顺序，把开始前的路程标出来；不能为了对齐，把尚未发生的并行画出来。

对齐方式

所有横条从同一条 cycle 0 竖线出发。斜纹段 = 从 kernel 起点到该指令开始前已经经过的时间；实色段 = 指令实际执行。斜纹不是这条指令的阻塞时间，包含前序工作、重叠执行和等待。

中间实验
开始前已过去的时间（不是 stall 归因）G0–G3：LD 搬行F0：VP 清零S0：ST 写回
读 G0 这一对：Before 先经过 898 cy，再执行 114 cy；After 先经过 514 cy，再执行 113 cy。主要变化是提前开始了 384 cy，执行本身只少 1 cy。
收益主要发生在开始搬运之前。 四条数据行 LD 的执行时长合计只从 460 降到 452 cycles，最终 ST 前后都是 116 cycles。不是少搬数据，也不是 DMA 带宽提升了 22%。

用更多静态代码换更少动态控制开销。测试均不含 PE，收益属于抽取的 gather pattern，不外推为完整 MoE 的收益。

gather-unroll-limit=16：匹配规则与回退

在非末维 gather、末维 stride=1 且长度大于 1、生成的行循环次数为静态值且不超过阈值时，全展开该循环。16 是策略阈值，不是硬件常量，也不是“展开 16 次一定最快”的证明；设为 0 关闭。

动态 / 大行数、1D / 末维 gather、singleton payload、非连续 payload 和 scatter 保留原路径。共享、output-dependent、非 identity 或不满足纯整数比较/布尔运算检查的 mask 保留 tensor 物化。用户外循环不在展开范围。

数值正确性与已知未覆盖问题
  • FULL 构建成功，默认测试 822/822 PASS。
  • 4/8/16 行 full、全 masked、三 block 混合 mask、偶数列 tail：六组 VCS 完整输出 bit-exact。无效行使用 poisoned id，有效行覆盖重复 source row。
  • 最终源码生成的六组 zbin、输入和 golden 与验收 job 逐字节一致；构建时间字段用 SOURCE_DATE_EPOCH 固定。
  • 原始 MoE case 只验证到 ASM 编译，没有跑完整 MoE RTL。
  • 奇数 BF16 tail（K=95，k_offset=16）前后均存在相同错误输出，本 MR 未修复；偶数列 tail PASS 不代表任意 tail 都正确。
  • 早期 8/16 行与多 block 的不完整分配实验已经作废，本页引用的是修正后完整重跑结果。
为什么还不能说已达到最少 cycles？

运行时源地址计算、逐行 descriptor 配置和 CT_MAIL / LD_MAIL 等等待仍在。修复后四行 LD 的启动间隔约 223、223、222 cycles，每行 LD 自身约 113 cycles。行间控制路径还值得分析，但不能把二者差值直接当作可消除时间。

本 MR 证明了这类 pattern 的 lowering 可以更快；还没有证明全局最优，也没有扩大到地址位宽、后端调度或新的 gather 硬件映射。
