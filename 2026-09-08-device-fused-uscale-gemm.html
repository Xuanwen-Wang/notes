TritonShared - Device-Fused UScale GEMM

Zeus 的 PE 只有一条 scale 通路，且固定挂在 weight 侧。这意味着 activation 的 per-group 量化 scale 在硬件上没有地方可放。本次编译团队打通的能力，是让 kernel 在设备侧把 activation scale 乘进 weight 的 UScale，再交给 PE —— 不需要 host 预处理，不需要额外的反量化 pass，tl.dot 本身也不改。

现在有两种放置方案可选，数值语义完全一致，区别只在 fused UScale 存在哪里、以及 weight slab 是否需要可写。两个参考 kernel 都已合入 master，可以直接拿去改。

✓

一句话总结：准备好 origin_uscale（weight 自己的 per-channel scale，已按 WUS 页格式排好）和 activation_scale（算法侧原生的 [M, K/UGROUP]），kernel 会在每个 M row 开始前把两者相乘写进 WUS 页，然后照常做 blocked GEMM。PE 每吃满一个 UGROUP 就自动换一次 scale。

一、这个特性解决什么问题

FP8 / INT8 GEMM 里，activation 和 weight 通常都沿 K 方向做 per-group 量化：每 UGROUP 个 K 共享一个 scale。反量化后的真实结果是

out[m,n] = Σg Σk∈g ( actq[m,k] · act_scale[m,g] ) · ( wq[n,k] · w_uscale[n,g] )

两个 scale 在同一个 group 内都是常数，可以提到求和外面：

out[m,n] = Σg ( act_scale[m,g] · w_uscale[n,g] ) · Σk∈g actq[m,k] · wq[n,k]

括号里那一项就是 fused UScale。它只依赖 (m, n, g)，与 K 无关，因此可以在 GEMM 之前算好，PE 照常做纯整数/FP8 的 MAC。

为什么不能让 activation 自己带 scale

activation
侧
硬件上没有 scale 通路。GDG → L2 → PE 的 activation 数据路径是纯搬运，PE 读进来直接进 MAC 阵列，中间没有任何逐 group 乘系数的硬件。
weight
侧
有且只有一条 WUS 通路。weight 从 weight DRAM 经 WL1 进 PE，WL1 上挂着 UScale 单元，每消费满 UGroup 个 K 就换用下一个 scale，按输出通道 n 索引。这条通路本来是给 weight 的 per-channel 量化用的。
所以做法只能是：把 activation 的 scale 提前乘进 weight 的 UScale，让这条唯一的通路同时承载两侧的量化系数。这就是 fused UScale 的全部含义 —— 不是新硬件，而是把两个 scale 合并到硬件已有的那一条通路上。

代价是：fused UScale 依赖 m，而原本的 weight UScale 不依赖。所以每处理一个 activation row，都要重算一遍整块 weight 的 fused UScale。这也是当前 BLOCK_M 固定为 1 的原因。

二、硬件给了什么

整条链路上，跟这个特性直接相关的硬件事实只有下面几条。它们决定了 ABI 长什么样，也决定了哪些写法会静默算错。

PE_SETM_U
PE 的 scale 配置指令，带 UEN（开关）、UGroup（每多少个 K 换一次 scale）、USaddr（scale 在 weight DRAM 里的位置）。kernel 作者不直接写这条指令，编译器从 tl.load(..., ugroup=, uscale=) 推导。
USaddr
粒度
USaddr 是相对本 core weight DRAM 基址的 16 KiB 页号，不是字节地址。RTL 实际只取寄存器低 20 位，寻址范围 16 GiB。所以 UScale 的存放位置必须按 16 KiB 对齐。
WUS 页
一个物理页 = 8 个 WL1 lane × 每 lane 1024 个 BF16 = 16 KiB，可装 8192 个系数。8 和 1024 都是硬件固定值。一个 weight block 配一个 UScale block；装不下一页时就占连续多页（32 KiB、48 KiB…），页数记作 S。硬件、forward_transform_uscale、两套 simulator 与生产 host 打包器一直都按 S 页处理，参考 kernel 现在也已支持任意 S，见第三节。
位置
自由度
RTL 里 UScale 的读地址只由 USaddr 推导，与 weight 自己的地址无关 —— 硬件不要求 UScale 紧邻 weight。这一条是方案二能成立的基础。

四、把 fused UScale 放在哪里

fused UScale 必须落在 weight DRAM 里、并且让 USaddr 指得到。放的位置有两种做法，数值完全等价。

默认请用方案一。Zeus 的 weight 与 UScale 都在 3D DRAM 的近存结构里，PE 做一次 PE_CONV 会先后取这个 block 的 weight 和它的 UScale。两者物理上离得越近，越容易命中同一片近存区域，避免来回切换带来的 cache miss。方案一把每个 block 的 UScale 直接排在它自己的 weight 后面，天然满足这个局部性；方案二让 PE 每个 block 都要在两块相距较远的区域之间跳。除非确实需要 weight 保持只读，否则不要用方案二。

为什么 act scale 是最朴素的形状

这一版特意没有要求算法侧做任何重排。kernel 把 [M, K/UGROUP] 读成 [1, 1, G, 1]，由硬件沿页最内轴（16 个连续通道）做 C 方向广播，整页仍然只用一条 VP 完成相乘。

中途曾经用过 lane-major 的 [M, N/R, K/UGROUP, R]。它在 BLOCK_N=128 下能工作，但按第三节的真实编址要展开成 [M, lane, kg, g, row16] 五个轴，而 tl.make_block_ptr 只有四维 —— BLOCK_N > 128 时根本摆不下。朴素形状不但能泛化，实测还更快：同形状下 4,828 对 4,968 cycles，因为读 G 个标量比读 8×G×16 个复制值省 LD 指令（27 对 31）。

六、Kernel 怎么写

两个参考 kernel 都是同一个两阶段结构。对每个 activation row：先把这一行对应的全部 fused UScale 页写完，再做这一行的 blocked GEMM。

阶段 1
更新 scale
遍历所有 weight block；每个 block 内再按 kg（128 通道 super-group）拆。每轮：2 条 LD（origin UScale 一块 [8, G, 16] + act scale 一份 [1, 1, G, 1]）→ 1 条 VP（相乘，C 方向广播）→ 1 条 ST（写页对应区间）。
阶段 2
GEMM
标准 blocked GEMM。weight 用 tl.load(..., memory_type="weight", ugroup=UGROUP)；方案二额外传 uscale=arena_base + block_idx * PAGE。tl.dot 不增加任何 scale 参数。

            shape=(total_weight_blocks, 8, USCALE_ROWS_PER_PAGE_LANE, 16),
            strides=(PAGE_ELEMS, 1024, 16, 1),
            offsets=(block_idx, 0, row_start, 0),
            block_shape=(1, 8, G, 16),          # tile = (lane, g, row16)，C = 16
            order=(3, 2, 1, 0),
        ),
        memory_type="weight",
    )

    act_narrow = tl.load(                        # 算法侧原生形状，读成 [1,1,G,1]
        tl.make_block_ptr(
            base=activation_scale_ptr,
            shape=(M, 1, padded_k_groups, 1),
            strides=(padded_k_groups, padded_k_groups, 1, 1),
            offsets=(m_start, 0, first_k_group, 0),
            block_shape=(1, 1, G, 1),
            order=(3, 2, 1, 0),
        ),
    )

uscale= 不产生任何数据搬运。编译器把这个指针折算成 PE_SETM_U 的 USaddr，并自动建立"ST 写 arena → PE 读 arena"的同步依赖。方案一不需要这个参数，编译器按邻接规则推导。

为什么要按 kg 拆循环。kg·(G·16) + g·16 + row 和 (kg·G + g)·16 + row 描述的是同一段内存，但交给 DMA 的 tile 形状不同。C 必须等于硬件的 16 行粒度：把 g 折进 C（变成 C = G·16）会让描述符退化成一堆小传输，实测同形状下 LD 指令 31 → 157、CT 1,017 → 3,889、wall 4,968 → 23,301（4.7 倍回退），而 PE/VP 的工作量一模一样。反过来若保持 C=16 却想让 act scale 沿 W 轴平铺，reshape 出来的视图不 compact，会被 VP matrix C-broadcast requires a proven compact SrcB view 拒掉。按 kg 拆开两个问题一起解决，BLOCK_N=128 时循环退化成 1 次、零代价。

七、硬性约束清单

下面每一条都是会导致静默错误或编译失败的边界，不是建议。

  • BLOCK_M 必须为 1不同 activation row 的 scale 不同，而一个 weight block 只有一份 fused UScale block。要支持 BLOCK_M > 1 需要每行一份，属于后续工作。
  • BLOCK_N 必须是 128 的整数倍128 = 8 lane × 16 row 是一个完整的 super-group。不是整数倍时页内编址无法闭合。
  • USCALE_PAGES 必须等于 ⌈BLOCK_N × (BLOCK_K/UGROUP) / 8192⌉即一个 UScale block 占几个 16 KiB 页（≤ 8192 时为 1，≤ 16384 时为 2，依此类推）。多页已完整支持。填小了 ALIGNED_SPACE 会少算一页、block stride 错位而静默读到别的 block；填大了同样错位。两种都不报错只会数值全错，所以 kernel 内用 static_assert 在编译期挡住。
  • G = BLOCK_K / UGROUP 必须整除 64每个 kg 占 G 个 16 行格子，只有 G | 64 时这些格子才不横跨页边界，一个 kg 才能用一条 DMA 描述完。BLOCK_K 与 UGROUP 都是 2 的幂时自动满足；G > 64 被 static_assert 拒绝。这是 kernel 侧 4 维 block ptr 的表达能力限制，不是数据布局限制。
  • UScale 存放位置必须 16 KiB 对齐USaddr 以 16 KiB 页为单位。方案二的 arena 基址和每一页都要对齐；仿真框架的 weight DRAM 分配器已相应改为 16 KiB 对齐。
  • K 必须按 UGROUP 对齐BLOCK_K 可以包含多个 UGROUP，不要求 BLOCK_K == UGROUP，但 quant group 必须完整落在 block 内。
  • 每个 core 的 N 必须按 BLOCK_N 对齐多核时 N 先切给 core，再按 BLOCK_N 分块。
  • activation 与 weight 的 UGROUP 必须相同fused UScale 是两者逐 group 相乘，group 边界不一致就没有意义。
  • act scale 的 K-group 轴要 padding 到 ⌈K/BLOCK_K⌉ × Gboundary_check 在硬件上是裁 tile 尺寸而不是补零，被裁掉的部分在 L2 里留的是未初始化数据。padding 后由 kernel 自己的 mask 置零。
  • fused UScale 的宿主不能被并发共享方案一是 packed_weight，方案二是 arena。同一块不能被多个未完成的 invocation 使用；并发或 graph replay 由调用方按 slot 轮转。kernel 返回时其中保留最后一个 M row 对应的 fused UScale。
  • 页内 padding 不被写入kernel 只写有效区。宿主参数是 inout，padding 保留调用方传入的原值 —— 如果调用方要求 padding 为特定值（例如逐字节比对），需要自己预置。

本 example 是 fused UScale 的首个参考实现，采用**方案一（邻接原地更新）**：
每个 weight block 后面紧跟属于它自己的 fused UScale block（S 个连续 16 KiB
物理页），设备侧算完直接原地覆盖，kernel ABI 不传独立的 fused_uscale 指针。

===============================================================================
1. 为什么需要 fused UScale
===============================================================================

PE 硬件只有**一条** scale 通路，且挂在 weight 侧（WL1）。activation 侧没有
任何 scale 通路，所以 act 的 per-group scale 只能在进 PE 之前就物化掉。做法
是把它乘进 weight UScale：

    out[m,n] = Σ_k act[m,k]·w[n,k]
             = Σ_g  Σ_{k∈g} (act_q[m,k]·act_scale[m,g]) · (w_q[n,k]·w_uscale[n,g])
             = Σ_g  act_scale[m,g]·w_uscale[n,g] · ( Σ_{k∈g} act_q[m,k]·w_q[n,k] )
                    └──────── fused_uscale[n,g] ────────┘   └───── PE 负责 ─────┘

PE 每吃满 UGROUP 个 K 就自动换一次 scale，换的是**按输出通道 n 索引**的那一个
（weight 量化本来就是 per-channel）。所以 fused UScale 必须铺满 [BLOCK_N, G]，
即使 act_scale 沿 n 是常数 —— 那 G 个值被广播了 BLOCK_N 遍。

===============================================================================
2. 记号：WUS 页的通道编址
===============================================================================

**术语：WUS = Weight UScale**，挂在 WL1 上的 weight 量化系数。理解本 example
先要理清三层关系：

    weight block        BLOCK_N × BLOCK_K 个 FP8 权重
         ↕ 一一配对
    UScale block(WUS)   BLOCK_N × G 个 BF16 系数，G = BLOCK_K / UGROUP
         ↕ 按 16 KiB 物理页存放
    物理页              1 页 = 8 个 WL1 lane × 每 lane 1024 个 BF16
                        = 8192 个 BF16 = 16 KiB

**每个 weight block 配一个属于它自己的 UScale block。** weight 沿 K 每 UGROUP
个元素共用一个量化系数，而系数按输出通道 n 索引（weight 量化本来就是
per-channel），所以一个 block 需要 BLOCK_N × G 个系数 —— 即使 act scale 沿 n
是常数，也要铺满这 BLOCK_N 行。方案一把 UScale block 紧跟在自己的 weight block 后面（见 §3）。

**为什么会有多页。** 硬件读 UScale 的最小单位是 16 KiB 的页，起始地址也必须
16 KiB 对齐，所以既不存在更小的粒度、也只能按整页递增。一页装 8192 个 BF16：

    页数 S = ⌈BLOCK_N × G / 8192⌉

      BLOCK_N × G ≤  8192   → S = 1  （16 KiB）
      BLOCK_N × G ≤ 16384   → S = 2  （32 KiB）
      以此类推

    换算成 weight 规模：需要多页 ⟺ BLOCK_N × BLOCK_K > 8192 × UGROUP。
    UGROUP=128 时即单个 weight block 超过 1 M 个元素（FP8 权重 1 MiB）。
    实践中触发多页的典型场景是细粒度量化（UGROUP=32/64 把门槛降到
    256 K / 512 K）或大 BLOCK_N × 大 BLOCK_K 的驻留式分块。

    本 example：BLOCK_N=256、G=8 → 256×8 = 2048 ≤ 8192，**S = 1**（16 KiB），
    只用掉一页容量的 1/4，其余是页内 padding。

S > 1 时这 S 个页在 DRAM 里**连续排列**；PE 的 USaddr 只指向第一页，后续页由
硬件的地址生成器按 tk/tc 计数器自己走过去（VCS 实证 job 23a02ed4fcc0）。
S 由 `USCALE_PAGES` 这个 constexpr 显式声明（`constants` 表里一眼可见），
并在 kernel 内用 static_assert 校验它等于几何推出的
⌈BLOCK_N × G / 8192⌉ —— 与 `forward_transform_uscale` 的 padded_2K 同一公式，
填错编译期即报错。详见 §3 末尾。

    G    = BLOCK_K / UGROUP        每个 weight block 含多少个 K quant group
    lane ∈ [0, 8)                  WL1 lane
    row  ∈ [0, 16)                 lane 内的行；**16 是硬件固定的行粒度**
    kg   ∈ [0, BLOCK_N / 128)      输出通道的 128 通道 super-group 下标

    n = kg * 128 + lane * 16 + row          输出通道号

本 example：BLOCK_N=256, BLOCK_K=1024, UGROUP=128 → G = 8, kg ∈ {0, 1}

★ **不要把它写成 `n = lane * (BLOCK_N/8) + row`。** 那个式子只在 BLOCK_N=128
  时碰巧成立（此时 kg 只有一个，且 BLOCK_N/8 恰好等于硬件粒度 16），
  BLOCK_N 一旦变大就会静默算错 —— 输出量级正常、逐通道乱掉，很难从症状
  反推到 layout。权威定义见
  `sim_check/sim_framework/weight/transform.py:forward_transform_uscale`。
  本 example 特意取 BLOCK_N=256（kg 有两个）来覆盖通用路径。

    lane 7    │ n=112..127              │ n=240..255              │       │
              └─────────────────────────┴─────────────────────────┴───────┘

    每个 (kg, g) 格子里是 **16 个连续输出通道**（上面只标了 g0 那一格的 n，
    同一 kg 内 g1..g7 覆盖的是同一批通道、不同的 K quant group）；
    相邻 lane 相差 16 个通道，相邻 kg 相差 128 个通道。

页容量 8 × 1024 = 8192 个 BF16 是硬件固定的；逻辑有效数据是 BLOCK_N × G 个
（本 example 2048 个，占单页的 1/4），其余是页内 padding。

**UScale 区域是带 page 的**：16 KiB 只是硬件的页粒度（8 lane × 每 lane 1024
BF16），不是区域上限。区域大小 = S × 16 KiB：

    S = ⌈BLOCK_N × G / 8192⌉        每个 weight block 占几页

    S = 1（16 KiB）⟺ BLOCK_N × G ≤ 8192   ← 本 example 属于这一档
    S = 2（32 KiB）⟺ 8192 < BLOCK_N × G ≤ 16384
    以此类推

本 kernel 已支持任意 S：页数由 `USCALE_PAGES` 声明并经 static_assert 校验，
`KG_PER_PAGE` 把 kg 拆成 (页号, 页内起始格子) 展开寻址，S=1 时折叠回单页写法、
零运行时代价。S=2 的参考配置见
`..._fused_uscale_2page_bf16dst_f32acc_1x4096x512_1core.py`。

`USCALE_PAGES` 作为 constexpr 显式传入，让调用方一眼看到这个 kernel 的 UScale
block 占几页；但它**不是自由量** —— 由 (BLOCK_N, BLOCK_K, UGROUP) 唯一决定，与
`forward_transform_uscale` 的 padded_2K 同一公式。kernel 内的 static_assert 强校验
两者一致：填小了 ALIGNED_SPACE 会少算一页、block stride 错位而静默读到别的 block，
填大了同样错位，两种都不报错只是数值全错，所以必须在编译期挡住。

===============================================================================
4. GDG 排布：act scale 用最朴素的形状
===============================================================================

    activation_scale: [M, K/UGROUP_padded]
                       │   └── K-group，padding 到 ⌈K/BLOCK_K⌉ × G
                       └── token

**算法侧产出什么就传什么** —— per-128 量化本来就是这个形状，不需要按 WL1 lane
重排，也不需要知道页的几何。

kernel 侧读成 [1, 1, G, 1]，由硬件沿页最内轴（16 个连续通道）做 C 方向广播，
**整页仍然只用一条 VP**。

这个 ABI 不但不比 lane-major 慢，实测还略快：同形状（BLOCK_M=1, BLOCK_K=1024,
BLOCK_N=128, M=2/K=1024/N=128，VCS 带 trace）**4,828 cy vs lane-major 的
4,968 cy（−2.8%）**，因为只读 G 个标量比读 8×G×16 个 lane-major 值省 LD
（LD 指令 27 vs 31，CT 955 vs 1,017）。

曾经用过 lane-major `[M, N/R, K/UGROUP_pad, R]`（R = BLOCK_N/8）：它在
BLOCK_N=128 下能工作，但按 §2 的真实编址要展开成 [M, lane, kg, g, row16]
五个轴，而 tl.make_block_ptr 只有四维 —— BLOCK_N > 128 时根本摆不下。

K-group 轴 padding 到 BLOCK_K 的整数倍，是为了让最后一个 block 也能读满 G 个
group 而不越界 —— boundary_check 在硬件上是**裁 tile 尺寸**而非补零，被裁掉
的部分在 L2 里留的是未初始化数据。

===============================================================================
5. 执行语义
===============================================================================

BLOCK_M 固定为 1：fused UScale 紧贴 weight block，一个 block 只有一份 WUS 区域，
而不同 token 的 act scale 不同，所以只能逐 token 重算。对每个 M row：

    for each weight block:
      for kg in range(BLOCK_N / 128):          # 见下面「为什么按 kg 拆」
        LD  origin weight UScale [8, G, 16]  ─┐
        LD  act scale [1, G, 1]              ─┼→ VP 相乘 → ST 覆盖对应的页区间
    然后执行该 row 的标准 blocked GEMM
        weight 仍走 tl.load(..., memory_type="weight", ugroup=UGROUP)，
        tl.dot 不增加任何 scale 参数

-------------------------------------------------------------------------------
★ 为什么按 kg 拆循环，而不是把 (g, row16) 合成一个 G*16 的最内轴
-------------------------------------------------------------------------------

两种写法描述的是同一段内存（kg*(G*16) + g*16 + row ≡ (kg*G + g)*16 + row），
但交给 DMA 的 tile 形状不同：

    本 kernel   tile = (lane=8, g=G, row=16)      C = 16    ✓
    合并写法    tile = (lane=8, kg=N_SUPER, GG)   C = G*16  ✗

**C 必须等于硬件的 16 行粒度。** 把 g 折进 C 会让描述符退化成一堆小传输 ——
实测同形状下 LD 指令 31 → 157、CT 1,017 → 3,889、wall **4,968 → 23,301
（4.7 倍回退）**，而 PE/VP 的工作量一模一样。

反过来，若保持 C=16 而想让 act scale 沿 W 轴（kg,g 合并轴）平铺，reshape
出来的视图不 compact，会被 "VP matrix C-broadcast requires a proven compact
SrcB view" 拒掉。按 kg 拆开后每次的 scale 就是同一份 [1, G, 1]，两个问题
一起解决；BLOCK_N = 128 时循环退化成 1 次，零代价（实测与不拆完全同 cycle）。

K 非 BLOCK_K 整数倍时，尾部 group 必须显式写 0（同一份 packed slab 会被后续
M row 复用，不写会残留上一行的 fused scale）。该 guard 由 K_ALIGNED constexpr
在编译期择路，对齐 shape 不付任何代价 —— 详见下面 resolve_constants。

===============================================================================
6. ABI 与约束
===============================================================================

* ``activation_fp8_ptr``   GDG 只读，逻辑 [M, K]。
* ``activation_scale_ptr`` GDG 只读，[M, K/UGROUP_padded]，见 §4。
* ``packed_weight_ptr_list``  GDG 中 [CORE_NUM] 个 i64 地址 → 本 core 的 LDG
                              inout 区，combined unit 排布见 §3。
* ``origin_uscale_ptr_list``  GDG 中 [CORE_NUM] 个 i64 地址 → 本 core 的只读
                              LDG，每 block S 个连续物理 WUS 页（本 example S=1）。
* ``output_ptr``           GDG 写出，逻辑 [M, N] 的 BF16。

约束：

* M 是运行时维度；BLOCK_M 固定为 1。
* K 必须按 UGROUP 对齐；BLOCK_K 可含多个 UGROUP（不要求 BLOCK_K == UGROUP）。
* 每个 core 的 N 必须按 BLOCK_N 对齐，且 BLOCK_N 必须是 128 的整数倍
  （128 = 8 lane × 16 row 是一个 super-group）。
* UScale 区域按 16 KiB 分页，一个 block 占 S = ⌈BLOCK_N × G / 8192⌉ 个
  相邻的连续 WUS 页（G = BLOCK_K / UGROUP，见 §3）。
  BLOCK_N × G ≤ 8192 时 S=1（16 KiB），≤ 16384 时 S=2（32 KiB），以此类推。
  S 由 constexpr `USCALE_PAGES` 显式声明，并经 static_assert 校验与几何一致。
* G 必须整除 64，否则单个 kg 的 scale 段会横跨页边界（kernel 侧 static_assert
  拒绝）。BLOCK_K 与 UGROUP 均为 2 的幂时自动满足。
* activation 与 weight 必须用相同的 UGROUP。
* 同一份 packed_weight 不能被多个 invocation 并发更新；kernel 返回时其中保留
  最后一个 M row 对应的 fused UScale。
"""


import triton
import triton.language as tl


@triton.jit
def gemm_fused_uscale_fp8xfp8_kernel(
    activation_fp8_ptr,           # GDG readonly；FP8 [M, K]
    activation_scale_ptr,         # GDG readonly；BF16 per-group scale [M, K / UGROUP, N]
    packed_weight_ptr_list,       # GDG [CORE_NUM] 地址表 -> LDG inout [weight block][物理 WUS page]
    origin_uscale_ptr_list,       # GDG [CORE_NUM] 地址表 -> LDG readonly；每个 block 逻辑 [BLOCK_N, BLOCK_K / UGROUP]，物理 USCALE_PAGES 个 WUS page [8, 1024]
    output_ptr,                   # GDG writeonly；BF16 [M, N]
    M,                            # 运行时 i32 标量；GEMM M
    K,                            # 运行时 i32 标量；GEMM K
    N,                            # 运行时 i32 标量；GEMM N
    CORE_NUM: tl.constexpr,       # 编译期标量；PE core 数
    BLOCK_M: tl.constexpr,        # 编译期 M tile；当前只支持 1
    BLOCK_K: tl.constexpr,        # 编译期 K tile；必须是 UGROUP 的整数倍
    BLOCK_N: tl.constexpr,        # 编译期 N tile；packed weight block 的 N 维
    UGROUP: tl.constexpr,         # 编译期标量；activation/weight 沿 K 的量化粒度
    USCALE_PAGES: tl.constexpr,   # 编译期标量；一个 UScale block 占几个 16 KiB 物理 WUS 页
                                  #   = ceil(BLOCK_N * (BLOCK_K/UGROUP) / 8192)，见 §2/§3
    K_ALIGNED: tl.constexpr,      # 编译期标量；K 是否为 BLOCK_K 的整数倍
):
    """逐 activation row 更新相邻 fused UScale，再执行 block GEMM。"""
    # 物理 WUS 页由 8 个 WL1 lane 组成，每个 lane 固定占 1024 个 BF16。
    USCALE_ELEMENT_BYTES: tl.constexpr = 2
    USCALE_LANES: tl.constexpr = 8
    USCALE_LANE_STRIDE_BF16: tl.constexpr = 1024
    # 页的真实几何 (权威来源 forward_transform_uscale):
    #   页内偏移 = lane*1024 + kg*(G*16) + g*16 + row16
    #   输出通道 n = kg*128 + lane*16 + row16,  kg ∈ [0, BLOCK_N/128)
    # 每 lane 的行粒度恒为 16, 外层套 128 通道的 super-group。
    # 注意 BLOCK_N/8 那套只在 BLOCK_N=128 时碰巧成立。
    USCALE_ROW_GRANULE: tl.constexpr = 16
    USCALE_CHANNELS_PER_SUPER: tl.constexpr = (
        USCALE_LANES * USCALE_ROW_GRANULE
    )
    N_SUPER_GROUPS: tl.constexpr = BLOCK_N // USCALE_CHANNELS_PER_SUPER
    USCALE_PAGE_BF16_ELEMS: tl.constexpr = (
        USCALE_LANES * USCALE_LANE_STRIDE_BF16
    )
    GROUPS_PER_WEIGHT_BLOCK: tl.constexpr = BLOCK_K // UGROUP
    # 页里每个 lane 覆盖 (kg, g) 两级共 N_SUPER*G 行, 每行 16 个连续通道。
    PAGE_ROWS_PER_LANE: tl.constexpr = (
        N_SUPER_GROUPS * GROUPS_PER_WEIGHT_BLOCK
    )
    # 每个 lane 在一页里有 1024/16 = 64 个 16 行格子。
    USCALE_ROWS_PER_PAGE_LANE: tl.constexpr = (
        USCALE_LANE_STRIDE_BF16 // USCALE_ROW_GRANULE
    )
    # What: 一页装得下几个 kg, 以及一个 weight block 的 UScale 要几页。
    # Why:  16 KiB 只是硬件的页粒度, 不是 UScale 区域的上限 —— 区域可以是任意
    #   16 KiB 整数倍 (forward_transform_uscale 的 padded_2K 本来就按 1024 向上
    #   取整分段, 两套 simulator 和生产 host 打包器也都按页数 ceil 算大小)。
    #   BLOCK_N*G > 8192 时一页装不下, 必须按页拆开寻址。
    # Assumption: G 整除 64 (见下面的 static_assert), 于是每个 kg 的 G 个格子
    #   完整落在同一页内, 不会横跨页边界 —— 这样一个 kg 仍然只要一条 DMA。
    KG_PER_PAGE: tl.constexpr = (
        USCALE_ROWS_PER_PAGE_LANE // GROUPS_PER_WEIGHT_BLOCK
    )
    # USCALE_PAGES 由调用方在 constants 里显式声明, 让人一眼看到这个 kernel 的
    # UScale block 占几页; 但它不是自由量 —— 由 (BLOCK_N, BLOCK_K, UGROUP) 唯一
    # 决定, 与 forward_transform_uscale 的 padded_2K 同一公式。这里编译期强校验
    # 两者一致: 填小了 ALIGNED_SPACE 会少算一页、block stride 错位而静默读到别的
    # block; 填大了同样错位。两种都不报错只是数值全错, 所以必须 fail-loud。
    tl.static_assert(
        USCALE_PAGES == (N_SUPER_GROUPS + KG_PER_PAGE - 1) // KG_PER_PAGE,
        "USCALE_PAGES 必须等于 ceil(BLOCK_N * G / 8192), 即 UScale block 的页数",
    )
    WEIGHT_BYTES_PER_BLOCK: tl.constexpr = BLOCK_N * BLOCK_K
    ALIGNED_SPACE_BYTES: tl.constexpr = (
        WEIGHT_BYTES_PER_BLOCK
        + USCALE_PAGES
        * USCALE_PAGE_BF16_ELEMS
        * USCALE_ELEMENT_BYTES
    )
    ALIGNED_SPACE_BF16: tl.constexpr = (
        ALIGNED_SPACE_BYTES // USCALE_ELEMENT_BYTES
    )
    SEGMENTS_PER_UNIT: tl.constexpr = (
        ALIGNED_SPACE_BF16 // USCALE_LANE_STRIDE_BF16
    )
    SCALE_FIRST_SEGMENT: tl.constexpr = (
        WEIGHT_BYTES_PER_BLOCK
        // USCALE_ELEMENT_BYTES
        // USCALE_LANE_STRIDE_BF16
    )

    # BLOCK_M 必须为 1：不同 activation row 有不同的 scale，而一次 PE dot
    # 只能为整个 M tile 绑定同一份 weight UScale。
    tl.static_assert(BLOCK_M == 1, "每次 dot 只能消费一行 activation scale")
    # BLOCK_K 是 PE tile 宽度，不等于 quant group。一个 weight block 可以
    # 包含多个 UGROUP；只要求 group 完整落在 block 内，并且全部 scale
    # 能放进每个 WL1 lane 的物理区域。
    tl.static_assert(BLOCK_K % UGROUP == 0, "K block 必须包含整数个 quant group")
    tl.static_assert(
        BLOCK_N % USCALE_CHANNELS_PER_SUPER == 0,
        "输出通道必须能够均分成 128 通道的 super-group",
    )
    # UScale 区域可以跨多页 (见 USCALE_PAGES), 但要求 G 整除 64:
    # 每个 kg 占 G 个 16 行格子, 只有 G | 64 时这 G 个格子才不会横跨页边界,
    # 一个 kg 才能继续用一条 (lane, g, row16) 的 DMA 描述完。
    # BLOCK_K 与 UGROUP 都是 2 的幂时 G 自然是 2 的幂, G<=64 即自动满足;
    # G>64 (BLOCK_K >= 64*UGROUP) 会让单个 kg 就跨页, 这里 fail-loud 不支持。
    tl.static_assert(
        USCALE_ROWS_PER_PAGE_LANE % GROUPS_PER_WEIGHT_BLOCK == 0,
        "每个 K-group 段必须整除页内行数 (G | 64), 否则 kg 会横跨 WUS 页边界",
    )

    core_id = tl.program_id(axis=0)
    n_per_core = N // CORE_NUM
    total_m_blocks = tl.cdiv(M, BLOCK_M)
    total_n_blocks = tl.cdiv(n_per_core, BLOCK_N)
    total_k_blocks = tl.cdiv(K, BLOCK_K)
    total_k_groups = tl.cdiv(K, UGROUP)
    # act scale 的 K-group 维按 BLOCK_K 对齐做 padding: 这样最后一个
    # weight block 读满 G 个 group 时也落在分配范围内(读到 padding 值),
    # 越界部分靠下面的 mask 置零。若改用 boundary_check, 它在硬件上是裁
    # tile 尺寸而非补零, 读回来的 tensor 形状会和 mask 对不上。
    padded_k_groups = total_k_blocks * GROUPS_PER_WEIGHT_BLOCK

    # 两个 ptr_list 自身位于 GDG；表项分别给出本 core 的可写 packed LDG
    # 和只读 original-USScale LDG 基地址。
    packed_weight_addr = tl.load(packed_weight_ptr_list + core_id)
    packed_slab_base = packed_weight_addr.to(tl.pointer_type(tl.bfloat16))
    packed_weight_base = packed_weight_addr.to(
        tl.pointer_type(tl.float8e4nv)
    )
    origin_uscale_addr = tl.load(origin_uscale_ptr_list + core_id)
    origin_uscale_base = origin_uscale_addr.to(
        tl.pointer_type(tl.bfloat16)
    )

    activation_template = tl.make_block_ptr(
        base=activation_fp8_ptr,
        shape=(M, K),
        strides=(K, 1),
        offsets=(0, 0),
        block_shape=(BLOCK_M, BLOCK_K),
        order=(1, 0),
    )
    output_template = tl.make_block_ptr(
        base=output_ptr,
        shape=(M, CORE_NUM, n_per_core),
        strides=(N, n_per_core, 1),
        offsets=(0, core_id, 0),
        block_shape=(BLOCK_M, 1, BLOCK_N),
        order=(2, 1, 0),
    )

    fused_uscale_offset = WEIGHT_BYTES_PER_BLOCK // USCALE_ELEMENT_BYTES
    total_weight_blocks = total_n_blocks * total_k_blocks

    # BLOCK_M 固定为 1，但 M 是任意运行时维度。每一行必须先完成自己的
    # fused-USScale 更新和 GEMM，才能让下一行安全复用同一批 LDG scale 槽。
    for m_block in range(total_m_blocks):
        m_start = m_block * BLOCK_M

        # 每个 weight block 的 fused UScale 按 kg 分次读-乘-写。
        # What: 一次覆盖 (lane, g, row16) = (8, G, 16), 每个 kg 只发
        #   2 条 LD + 1 条 VP + 1 条 ST, 而不是按 (lane, group) 段循环 8*G 轮。
        # Why: 一条 VP 算 128 个元素只要 4 拍却占 73 cy, 时间几乎只由指令条数
        #   决定。逐段版本在 M=2/K=1024/N=128 下 128 个 segment 吃掉 wall
        #   106,873 cy(LD 31,175 + ST 19,710), 而真正的 MAC 只占 265 cy ——
        #   固定开销完全主导。
        # Assumption: origin/fused 页与 act scale 能用同一套
        #   (lane, g, row16) 索引表达且 stride 递减 —— 页是 (1024, 16, 1),
        #   act scale 沿 g 变、由硬件在 row16 方向做 C 广播。
        # Not covered: 仍要求 G 整除 64 (见上面的 static_assert), 即单个 kg 的
        #   scale 段不横跨 WUS 页边界; 不改变页内布局和数值语义。
        for block_idx in range(total_weight_blocks):
            n_block = block_idx // total_k_blocks
            k_block = block_idx % total_k_blocks
            global_n_start = core_id * n_per_core + n_block * BLOCK_N
            first_k_group = k_block * GROUPS_PER_WEIGHT_BLOCK

            # 页里每个 lane 的 W 轴是 (kg, g) 两级: kg 是 128 通道的
            # super-group, g 是 K quant group, 每格 16 个连续输出通道。
            # 按 kg 拆开处理, 好处有两个:
            #   1. tile 保持 (lane, g, row16) = (8, G, 16), C=16 —— 与页内
            #      真实的连续性一致; 若把 g 和 row16 合成 C=G*16 交给 DMA,
            #      描述符会退化成一堆小传输(实测 LD 指令 31 -> 157, CT 3.8x,
            #      wall 4,968 -> 23,301)。
            #   2. act scale 只随 g 变, 每个 kg 用的是同一份 [1,1,G,1],
            #      直接做 C 方向广播即可; 若改成沿 W 平铺, reshape 出来的
            #      视图不 compact, 会被 "VP matrix C-broadcast requires a
            #      proven compact SrcB view" 拒掉。
            for super_group in tl.static_range(N_SUPER_GROUPS):
                # What: 把 kg 拆成 (页号, 页内起始格子) 两级。
                # Why:  BLOCK_N*G > 8192 时一个 block 的 UScale 占 S>1 页, kg 大到
                #   一定程度就落到后面的页里。S=1 时 KG_PER_PAGE >= N_SUPER,
                #   page 恒为 0、row_start 退化成 super_group*G, 与原写法逐字节等价。
                # Assumption: G | 64, 所以 kg 的 G 个格子不跨页 (见 static_assert)。
                page = super_group // KG_PER_PAGE
                row_start = (super_group % KG_PER_PAGE) * GROUPS_PER_WEIGHT_BLOCK
                # 第 1 轴取 S*8 长: 索引 = page*8 + lane, 配 stride 1024 后
                # 偏移 = page*8192 + lane*1024, 正好是「跨 16 KiB 页 + 页内 lane」。
                original_uscale = tl.load(
                    tl.make_block_ptr(
                        base=origin_uscale_base,
                        shape=(total_weight_blocks,
                               USCALE_PAGES * USCALE_LANES,
                               USCALE_ROWS_PER_PAGE_LANE,
                               USCALE_ROW_GRANULE),
                        strides=(USCALE_PAGES
                                 * USCALE_PAGE_BF16_ELEMS,
                                 USCALE_LANE_STRIDE_BF16,
                                 USCALE_ROW_GRANULE, 1),
                        offsets=(block_idx, page * USCALE_LANES, row_start, 0),
                        block_shape=(1, USCALE_LANES,
                                     GROUPS_PER_WEIGHT_BLOCK,
                                     USCALE_ROW_GRANULE),
                        order=(3, 2, 1, 0),
                    ),
                    memory_type="weight",
                )
                # act scale ABI 就是算法侧原本的 per-128 形状 [M, K/UGROUP],
                # 不需要按 WL1 lane 重排。这里读成 [1,1,G,1] 后由硬件沿
                # 16 个通道做 C 广播。
                act_narrow = tl.load(
                    tl.make_block_ptr(
                        base=activation_scale_ptr,
                        shape=(M, 1, padded_k_groups, 1),
                        strides=(padded_k_groups, padded_k_groups, 1, 1),
                        offsets=(m_start, 0, first_k_group, 0),
                        block_shape=(1, 1, GROUPS_PER_WEIGHT_BLOCK, 1),
                        order=(3, 2, 1, 0),
                    ),
                )
                # K 尾块的越界 group 必须置零(同一 slab 会被后续 M row 复用)。
                if K_ALIGNED:
                    fused_uscale = original_uscale * act_narrow
                else:
                    group_ids = tl.arange(
                        0, GROUPS_PER_WEIGHT_BLOCK
                    ).to(tl.float32)[None, None, :, None]
                    valid_groups = (
                        total_k_groups - first_k_group
                    ).to(tl.float32)
                    group_mask = tl.minimum(
                        tl.maximum(valid_groups - group_ids, 0.0), 1.0)
                    fused_uscale = (
                        original_uscale.to(tl.float32)
                        * act_narrow.to(tl.float32) * group_mask
                    ).to(tl.bfloat16)
                # combined unit 的第 1 轴以 1024 个 BF16 为一段, 一页正好 8 段,
                # 所以第 page 页的首段 = SCALE_FIRST_SEGMENT + page*8。形状与
                # stride 都不用动 —— 多页只是让 SEGMENTS_PER_UNIT 变大。
                tl.store(
                    tl.make_block_ptr(
                        base=packed_slab_base,
                        shape=(total_weight_blocks, SEGMENTS_PER_UNIT,
                               USCALE_ROWS_PER_PAGE_LANE,
                               USCALE_ROW_GRANULE),
                        strides=(ALIGNED_SPACE_BF16, USCALE_LANE_STRIDE_BF16,
                                 USCALE_ROW_GRANULE, 1),
                        offsets=(block_idx,
                                 SCALE_FIRST_SEGMENT + page * USCALE_LANES,
                                 row_start, 0),
                        block_shape=(1, USCALE_LANES,
                                     GROUPS_PER_WEIGHT_BLOCK,
                                     USCALE_ROW_GRANULE),
                        order=(3, 2, 1, 0),
                    ),
                    fused_uscale,
                    memory_type="weight",
                )

        # 当前行的 scale 更新结束后走标准 blocked GEMM。weight load 使用
        # 既有 WUS 路径读取相邻 fused UScale；tl.dot 本身不新增 scale 参数。
        for n_block in range(total_n_blocks):
            n_start = n_block * BLOCK_N
            accumulator = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

            for k_block in range(total_k_blocks):
                k_start = k_block * BLOCK_K
                block_idx = n_block * total_k_blocks + k_block

                activation = tl.load(
                    tl.advance(activation_template, (m_start, k_start)),
                    boundary_check=(0, 1),
                    padding_option="zero",
                )
                packed_block_byte_offset = block_idx * ALIGNED_SPACE_BYTES
                weight = tl.load(
                    tl.make_block_ptr(
                        base=packed_weight_base + packed_block_byte_offset,
                        shape=(BLOCK_N, BLOCK_K),
                        strides=(BLOCK_K, 1),
                        offsets=(0, 0),
                        block_shape=(BLOCK_N, BLOCK_K),
                        order=(1, 0),
                    ),
                    memory_type="weight",
                    ugroup=UGROUP,
                )
                accumulator += tl.dot(
                    activation,
                    tl.trans(weight),
                    out_dtype=tl.float32,
                )

            tl.store(
                tl.advance(output_template, (m_start, 0, n_start)),
                tl.expand_dims(accumulator.to(tl.bfloat16), 1),
                boundary_check=(0, 2),
            )

"""设备侧融合 activation scale 与 weight UScale 的标准 blocked FP8 GEMM。

本 example 采用**方案二（独立 arena）**：packed weight 只读且只含 weight
block，fused UScale 写进一块独立的 LDG arena，PE 通过显式绑定的 USaddr 去取。
方案一（邻接原地更新）见 ``gemm_normal_blocked_aligned_fp8xfp8_ugroup128_
fused_uscale_bf16dst_f32acc_1x1024x256_1core.py``，两者数值语义完全一致。

===============================================================================
1. 为什么需要 fused UScale
===============================================================================

PE 硬件只有**一条** scale 通路，且挂在 weight 侧（WL1）。activation 侧没有
任何 scale 通路，所以 act 的 per-group scale 只能在进 PE 之前就物化掉。做法
是把它乘进 weight UScale：

    out[m,n] = Σ_k act[m,k]·w[n,k]
             = Σ_g  Σ_{k∈g} (act_q[m,k]·act_scale[m,g]) · (w_q[n,k]·w_uscale[n,g])
             = Σ_g  act_scale[m,g]·w_uscale[n,g] · ( Σ_{k∈g} act_q[m,k]·w_q[n,k] )
                    └──────── fused_uscale[n,g] ────────┘   └───── PE 负责 ─────┘

PE 每吃满 UGROUP 个 K 就自动换一次 scale，换的是**按输出通道 n 索引**的那一个
（weight 量化本来就是 per-channel）。所以 fused UScale 必须铺满 [BLOCK_N, G]，
即使 act_scale 沿 n 是常数 —— 那 G 个值被广播了 BLOCK_N 遍。

===============================================================================
2. 记号
===============================================================================

**术语：WUS = Weight UScale**，挂在 WL1 上的 weight 量化系数。理解本 example
先要理清三层关系：

    weight block        BLOCK_N × BLOCK_K 个 FP8 权重
         ↕ 一一配对
    UScale block(WUS)   BLOCK_N × G 个 BF16 系数，G = BLOCK_K / UGROUP
         ↕ 按 16 KiB 物理页存放
    物理页              1 页 = 8 个 WL1 lane × 每 lane 1024 个 BF16
                        = 8192 个 BF16 = 16 KiB

**每个 weight block 配一个属于它自己的 UScale block。** weight 沿 K 每 UGROUP
个元素共用一个量化系数，而系数按输出通道 n 索引（weight 量化本来就是
per-channel），所以一个 block 需要 BLOCK_N × G 个系数 —— 即使 act scale 沿 n
是常数，也要铺满这 BLOCK_N 行。方案二把全部 UScale block 放在一块独立的 arena 里，weight 保持只读（见 §3）。

**为什么会有多页。** 硬件读 UScale 的最小单位是 16 KiB 的页，起始地址也必须
16 KiB 对齐，所以既不存在更小的粒度、也只能按整页递增。一页装 8192 个 BF16：

    页数 S = ⌈BLOCK_N × G / 8192⌉

      BLOCK_N × G ≤  8192   → S = 1  （16 KiB）
      BLOCK_N × G ≤ 16384   → S = 2  （32 KiB）
      以此类推

    换算成 weight 规模：需要多页 ⟺ BLOCK_N × BLOCK_K > 8192 × UGROUP。
    UGROUP=128 时即单个 weight block 超过 1 M 个元素（FP8 权重 1 MiB）。
    实践中触发多页的典型场景是细粒度量化（UGROUP=32/64 把门槛降到
    256 K / 512 K）或大 BLOCK_N × 大 BLOCK_K 的驻留式分块。

    本 example：BLOCK_N=256、G=8 → 256×8 = 2048 ≤ 8192，**S = 1**（16 KiB），
    只用掉一页容量的 1/4，其余是页内 padding。

S > 1 时这 S 个页在 DRAM 里**连续排列**；PE 的 USaddr 只指向第一页，后续页由
硬件的地址生成器按 tk/tc 计数器自己走过去（VCS 实证 job 23a02ed4fcc0）。
S 由 `USCALE_PAGES` 这个 constexpr 显式声明（`constants` 表里一眼可见），
并在 kernel 内用 static_assert 校验它等于几何推出的
⌈BLOCK_N × G / 8192⌉ —— 与 `forward_transform_uscale` 的 padded_2K 同一公式，
填错编译期即报错。详见 §3 末尾。

    G    = BLOCK_K / UGROUP        每个 weight block 含多少个 K quant group
    lane ∈ [0, 8)                  WL1 lane
    row  ∈ [0, 16)                 lane 内的行；**16 是硬件固定的行粒度**
    kg   ∈ [0, BLOCK_N / 128)      输出通道的 128 通道 super-group 下标

    n = kg * 128 + lane * 16 + row          输出通道号

本 example：BLOCK_N=256, BLOCK_K=1024, UGROUP=128 → G = 8, kg ∈ {0, 1}

★ **不要把它写成 `n = lane * (BLOCK_N/8) + row`。** 那个式子只在 BLOCK_N=128
  时碰巧成立（此时 kg 只有一个，且 BLOCK_N/8 恰好等于硬件粒度 16），
  BLOCK_N 一旦变大就会静默算错 —— 输出量级正常、逐通道乱掉，很难从症状
  反推到 layout。权威定义见
  `sim_check/sim_framework/weight/transform.py:forward_transform_uscale`。
  本 example 特意取 BLOCK_N=256（kg 有两个）来覆盖通用路径。

===============================================================================
3. LDG 排布（方案二：weight 与 UScale 分离）
===============================================================================

三块 LDG slab 各自独立，互不交织：

    packed_weight（只读）              fused_uscale arena（inout）
    ┌───────────────────────┐          ┌──────────────────┐
    │ block 0  BLOCK_N×BLOCK_K │       │ page 0  16 KiB   │  ← block 0 的 scale
    ├───────────────────────┤          ├──────────────────┤
    │ block 1               │          │ page 1  16 KiB   │
    ├───────────────────────┤          ├──────────────────┤
    │          ⋮            │          │        ⋮         │
    └───────────────────────┘          └──────────────────┘
                                       origin_uscale（只读）同序、同页布局

PE 取 scale 用的 USaddr 由 ``tl.load(..., uscale=page_ptr)`` 显式给出，编译器
把它折算成相对 arena base 的 16 KiB 页号，因此 weight 与 scale 的相对位置不再
被硬件固定。这正是与方案一的唯一结构差别：

| | 方案一 | 方案二 |
|---|---|---|
| weight slab | inout，含 UScale 页 | **只读，纯 weight** |
| USaddr 来源 | weight block 基址 + weight 字节数 | **arena 基址 + 页号** |
| 多流复用 | 同一份 weight 不能并发更新 | weight 可共享，arena 按 slot 轮转 |

代价是 PE 多读一块 weight DRAM slab，编译器需要为它单独登记同步资源。

-------------------------------------------------------------------------------
物理 WUS 页内部（8 个 WL1 lane，每 lane stride 1024 个 BF16，共 16 KiB）
-------------------------------------------------------------------------------

    page_offset(lane, kg, g, row) = lane*1024 + kg*(G*16) + g*16 + row

              ├──────────────── 每 lane 1024 个 BF16 ─────────────────┤
              ├──── kg=0 (G*16=128) ────┬──── kg=1 (G*16=128) ────┬─ pad ─┤
              │ g0 │ g1 │ … │ g7        │ g0 │ g1 │ … │ g7        │       │
    lane 0    │ n=0..15 (每格 16 个通道) │ n=128..143              │       │
    lane 1    │ n=16..31                │ n=144..159              │       │
      ⋮
    lane 7    │ n=112..127              │ n=240..255              │       │
              └─────────────────────────┴─────────────────────────┴───────┘

    每个 (kg, g) 格子里是 **16 个连续输出通道**（上面只标了 g0 那一格的 n，
    同一 kg 内 g1..g7 覆盖的是同一批通道、不同的 K quant group）；
    相邻 lane 相差 16 个通道，相邻 kg 相差 128 个通道。

页容量 8 × 1024 = 8192 个 BF16 是硬件固定的；逻辑有效数据是 BLOCK_N × G 个
（本 example 2048 个，占单页的 1/4），页内 padding kernel 不写，arena 作为 inout 参数保留
host 传入的原值。

**UScale 区域是带 page 的**：16 KiB 只是硬件的页粒度（8 lane × 每 lane 1024
BF16），不是区域上限。区域大小 = S × 16 KiB：

    S = ⌈BLOCK_N × G / 8192⌉        每个 weight block 占几页

    S = 1（16 KiB）⟺ BLOCK_N × G ≤ 8192
    S = 2（32 KiB）⟺ 8192 < BLOCK_N × G ≤ 16384
    以此类推                         ← 本 example S=1

本 kernel 已支持任意 S：页数由 `USCALE_PAGES` 声明并经 static_assert 校验，
`KG_PER_PAGE` 把 kg 拆成 (页号, 页内起始格子) 展开寻址，S=1 时折叠回单页写法、
零运行时代价。

`USCALE_PAGES` 作为 constexpr 显式传入，让调用方一眼看到这个 kernel 的 UScale
block 占几页；但它**不是自由量** —— 由 (BLOCK_N, BLOCK_K, UGROUP) 唯一决定，与
`forward_transform_uscale` 的 padded_2K 同一公式。kernel 内的 static_assert 强校验
两者一致：填错会让 arena 的 block stride 错位而静默读到别的 block，不报错只是数值
全错，所以必须在编译期挡住。

kernel 唯一的额外要求是 **G 整除 64**：每个 kg 占 G 个 16 行格子，只有 G | 64
时这 G 个格子才不横跨页边界，一个 kg 才能用一条 (lane, g, row16) 的 DMA 描述完。
BLOCK_K 与 UGROUP 都是 2 的幂时自动满足。

===============================================================================
4. GDG 排布：act scale 用最朴素的形状
===============================================================================

    activation_scale: [M, K/UGROUP_padded]
                       │   └── K-group，padding 到 ⌈K/BLOCK_K⌉ × G
                       └── token

**算法侧产出什么就传什么** —— per-128 量化本来就是这个形状，不需要按 WL1 lane
重排，也不需要知道页的几何。

kernel 侧读成 [1, 1, G, 1]，由硬件沿页最内轴（16 个连续通道）做 C 方向广播，
**整页仍然只用一条 VP**。

这个 ABI 不但不比 lane-major 慢，实测还略快：同形状（BLOCK_M=1, BLOCK_K=1024,
BLOCK_N=128, M=2/K=1024/N=128，VCS 带 trace）**4,828 cy vs lane-major 的
4,968 cy（−2.8%）**，因为只读 G 个标量比读 8×G×16 个 lane-major 值省 LD
（LD 指令 27 vs 31，CT 955 vs 1,017）。

曾经用过 lane-major `[M, N/R, K/UGROUP_pad, R]`（R = BLOCK_N/8）：它在
BLOCK_N=128 下能工作，但按 §2 的真实编址要展开成 [M, lane, kg, g, row16]
五个轴，而 tl.make_block_ptr 只有四维 —— BLOCK_N > 128 时根本摆不下。

K-group 轴 padding 到 BLOCK_K 的整数倍，是为了让最后一个 block 也能读满 G 个
group 而不越界 —— boundary_check 在硬件上是**裁 tile 尺寸**而非补零，被裁掉
的部分在 L2 里留的是未初始化数据。

===============================================================================
5. 执行语义
===============================================================================

BLOCK_M 固定为 1：一个 weight block 在 arena 里只有一份 WUS 区域，而不同 token 的
act scale 不同，所以只能逐 token 重算。对每个 M row：

    for each weight block:
      for kg in range(BLOCK_N / 128):          # 见下面「为什么按 kg 拆」
        LD  origin weight UScale [8, G, 16]  ─┐
        LD  act scale [1, G, 1]              ─┼→ VP 相乘 → ST 写 arena 对应区间
    然后执行该 row 的标准 blocked GEMM
        weight 走 tl.load(..., memory_type="weight", ugroup=UGROUP,
                          uscale=arena_base + block_idx * PAGE)，
        tl.dot 不增加任何 scale 参数

``uscale=`` 只做地址绑定，不产生数据搬运：编译器把该指针折算成 PE_SETM_U 的
USaddr（相对 arena base 的 16 KiB 页号）。ST 写 arena 与 PE 读 arena 之间的
RAW 依赖由编译器为该 slab 单独建立的同步资源保证。

-------------------------------------------------------------------------------
★ 为什么按 kg 拆循环，而不是把 (g, row16) 合成一个 G*16 的最内轴
-------------------------------------------------------------------------------

两种写法描述的是同一段内存（kg*(G*16) + g*16 + row ≡ (kg*G + g)*16 + row），
但交给 DMA 的 tile 形状不同：

    本 kernel   tile = (lane=8, g=G, row=16)      C = 16    ✓
    合并写法    tile = (lane=8, kg=N_SUPER, GG)   C = G*16  ✗

**C 必须等于硬件的 16 行粒度。** 把 g 折进 C 会让描述符退化成一堆小传输 ——
实测同形状下 LD 指令 31 → 157、CT 1,017 → 3,889、wall **4,968 → 23,301
（4.7 倍回退）**，而 PE/VP 的工作量一模一样。

反过来，若保持 C=16 而想让 act scale 沿 W 轴（kg,g 合并轴）平铺，reshape
出来的视图不 compact，会被 "VP matrix C-broadcast requires a proven compact
SrcB view" 拒掉。按 kg 拆开后每次的 scale 就是同一份 [1, G, 1]，两个问题
一起解决；BLOCK_N = 128 时循环退化成 1 次，零代价（实测与不拆完全同 cycle）。

K 非 BLOCK_K 整数倍时，尾部 group 必须显式写 0（同一块 arena 会被后续 M row
复用，不写会残留上一行的 fused scale）。该 guard 由 K_ALIGNED constexpr 在
编译期择路：**默认值是保守的 False（带 mask，恒正确）**，只有调用方执行了
``resolve_constants`` 并确认 K 对齐才升级成 True 拿掉 mask。默认值必须在这一
侧，因为并非所有调用方都会调 ``resolve_constants`` —— GEMM suite 就是先用默认
constants 编译一份 IR 再喂各个 dynamic，默认 True 会让它在 K 非对齐时静默丢掉
mask。详见下面 resolve_constants 的 CONTRACT 注释。

===============================================================================
6. ABI 与约束
===============================================================================

* ``activation_fp8_ptr``   GDG 只读，逻辑 [M, K]。
* ``activation_scale_ptr`` GDG 只读，[M, K/UGROUP_padded]，见 §4。
* ``packed_weight_ptr_list``  GDG 中 [CORE_NUM] 个 i64 地址 → 本 core 的**只读**
                              LDG，按 (n_block, k_block) 顺序排纯 weight block，
                              块后不跟 UScale 页。
* ``origin_uscale_ptr_list``  GDG 中 [CORE_NUM] 个 i64 地址 → 本 core 的只读
                              LDG，每 block S 个连续物理 WUS 页（本 example S=1）。
* ``fused_uscale_ptr_list``   GDG 中 [CORE_NUM] 个 i64 地址 → 本 core 的 inout
                              arena，与 origin_uscale 同序、同页布局。
* ``output_ptr``           GDG 写出，逻辑 [M, N] 的 BF16。

约束：

* M 是运行时维度；BLOCK_M 固定为 1。
* K 必须按 UGROUP 对齐；BLOCK_K 可含多个 UGROUP（不要求 BLOCK_K == UGROUP）。
* 每个 core 的 N 必须按 BLOCK_N 对齐，且 BLOCK_N 必须是 128 的整数倍
  （128 = 8 lane × 16 row 是一个 super-group）。
* UScale 区域按 16 KiB 分页，一个 block 占 S = ⌈BLOCK_N × G / 8192⌉ 个
  连续 WUS 页（G = BLOCK_K / UGROUP，见 §3）。
  BLOCK_N × G ≤ 8192 时 S=1（16 KiB），≤ 16384 时 S=2（32 KiB），以此类推。
  S 由 constexpr `USCALE_PAGES` 显式声明，并经 static_assert 校验与几何一致。
* G 必须整除 64，否则单个 kg 的 scale 段会横跨页边界（kernel 侧 static_assert
  拒绝）。BLOCK_K 与 UGROUP 均为 2 的幂时自动满足。
* activation 与 weight 必须用相同的 UGROUP。
* arena base 与其中每一页都必须 16 KiB 对齐（PE_SETM_U 的 USaddr 以 16 KiB
  为单位）。
* 同一块 arena 不能被多个未完成的 invocation 共享，并发或 graph replay 由调用
  方按 slot 轮转；kernel 返回时 arena 保留最后一个 M row 对应的 fused UScale。
  packed_weight 只读，因此可以跨 invocation 共享。
"""

import triton
import triton.language as tl


@triton.jit
def gemm_fused_uscale_separate_kernel(
    activation_fp8_ptr,           # GDG in  [M, K] fp8
    activation_scale_ptr,         # GDG in  [M, K//UGROUP_padded] bf16（算法侧原生 per-128 形状，见 §4）
    packed_weight_ptr_list,       # GDG [CORE_NUM] i64 -> LDG in    纯 weight block 序列，每块 [BLOCK_N, BLOCK_K]，块后不再跟 UScale page
    origin_uscale_ptr_list,       # GDG [CORE_NUM] i64 -> LDG in    original UScale，每 block USCALE_PAGES 个物理 page [8, 1024] bf16（同方案一）
    fused_uscale_ptr_list,        # GDG [CORE_NUM] i64 -> LDG inout fused UScale arena，每 block USCALE_PAGES 个物理 page [8, 1024] bf16 ← 方案二新增
    output_ptr,                   # GDG out [M, N] bf16
    M,                            # 运行时 i32 标量；GEMM M
    K,                            # 运行时 i32 标量；GEMM K
    N,                            # 运行时 i32 标量；GEMM N
    CORE_NUM: tl.constexpr,       # 编译期标量；PE core 数
    BLOCK_M: tl.constexpr,        # 编译期 M tile；当前只支持 1
    BLOCK_K: tl.constexpr,        # 编译期 K tile；必须是 UGROUP 的整数倍
    BLOCK_N: tl.constexpr,        # 编译期 N tile；weight block 的 N 维
    UGROUP: tl.constexpr,         # 编译期标量；activation/weight 沿 K 的量化粒度
    USCALE_PAGES: tl.constexpr,   # 编译期标量；一个 UScale block 占几个 16 KiB 物理 WUS 页
                                  #   = ceil(BLOCK_N * (BLOCK_K/UGROUP) / 8192)，见 §2/§3
    K_ALIGNED: tl.constexpr,      # 编译期标量；K 是否为 BLOCK_K 的整数倍
):
    """逐 activation row 写 arena 中的 fused UScale page，再执行 block GEMM。"""
    # 物理 WUS 页由 8 个 WL1 lane 组成，每个 lane 固定占 1024 个 BF16。
    # 页的真实几何 (权威来源 forward_transform_uscale):
    #   页内偏移 = lane*1024 + kg*(G*16) + g*16 + row16
    #   输出通道 n = kg*128 + lane*16 + row16,  kg ∈ [0, BLOCK_N/128)
    # 每 lane 的行粒度恒为 16, 外层套 128 通道的 super-group。
    # 注意 BLOCK_N/8 那套只在 BLOCK_N=128 时碰巧成立, 见文件头 §2。
    USCALE_LANES: tl.constexpr = 8
    USCALE_LANE_STRIDE_BF16: tl.constexpr = 1024
    USCALE_ROW_GRANULE: tl.constexpr = 16
    USCALE_CHANNELS_PER_SUPER: tl.constexpr = (
        USCALE_LANES * USCALE_ROW_GRANULE
    )
    N_SUPER_GROUPS: tl.constexpr = BLOCK_N // USCALE_CHANNELS_PER_SUPER
    USCALE_PAGE_BF16_ELEMS: tl.constexpr = (
        USCALE_LANES * USCALE_LANE_STRIDE_BF16
    )
    USCALE_ROWS_PER_PAGE_LANE: tl.constexpr = (
        USCALE_LANE_STRIDE_BF16 // USCALE_ROW_GRANULE
    )
    GROUPS_PER_WEIGHT_BLOCK: tl.constexpr = BLOCK_K // UGROUP
    # What: 一页装几个 kg, 一个 weight block 的 UScale 占几页。
    # Why:  16 KiB 是硬件页粒度而非区域上限; BLOCK_N*G > 8192 时 arena 里每个
    #   block 占 S 个连续页, 必须按页拆开寻址。S=1 时 KG_PER_PAGE >= N_SUPER,
    #   page 恒 0, 与原写法逐字节等价。
    # Assumption: G 整除 64, 每个 kg 的 G 个格子不跨页 (见下面的 static_assert)。
    KG_PER_PAGE: tl.constexpr = (
        USCALE_ROWS_PER_PAGE_LANE // GROUPS_PER_WEIGHT_BLOCK
    )
    # USCALE_PAGES 由调用方在 constants 里显式声明, 让人一眼看到这个 kernel 的
    # UScale block 占几页; 但它不是自由量 —— 由 (BLOCK_N, BLOCK_K, UGROUP) 唯一
    # 决定, 与 forward_transform_uscale 的 padded_2K 同一公式。这里编译期强校验
    # 两者一致: 填小了 ALIGNED_SPACE 会少算一页、block stride 错位而静默读到别的
    # block; 填大了同样错位。两种都不报错只是数值全错, 所以必须 fail-loud。
    tl.static_assert(
        USCALE_PAGES == (N_SUPER_GROUPS + KG_PER_PAGE - 1) // KG_PER_PAGE,
        "USCALE_PAGES 必须等于 ceil(BLOCK_N * G / 8192), 即 UScale block 的页数",
    )
    USCALE_ELEMS_PER_BLOCK: tl.constexpr = (
        USCALE_PAGES * USCALE_PAGE_BF16_ELEMS
    )
    # 方案二: packed weight 只含 weight block，block stride 就是 weight 字节数。
    WEIGHT_BYTES_PER_BLOCK: tl.constexpr = BLOCK_N * BLOCK_K

    # BLOCK_M 必须为 1：不同 activation row 有不同的 scale，而一次 PE dot
    # 只能为整个 M tile 绑定同一份 weight UScale。
    tl.static_assert(BLOCK_M == 1, "每次 dot 只能消费一行 activation scale")
    # BLOCK_K 是 PE tile 宽度，不等于 quant group。一个 weight block 可以
    # 包含多个 UGROUP；只要求 group 完整落在 block 内，并且全部 scale
    # 能放进每个 WL1 lane 的物理区域。
    tl.static_assert(BLOCK_K % UGROUP == 0, "K block 必须包含整数个 quant group")
    tl.static_assert(
        BLOCK_N % USCALE_CHANNELS_PER_SUPER == 0,
        "输出通道必须能够均分成 128 通道的 super-group",
    )
    # UScale 区域可以跨多页 (见 USCALE_PAGES), 但要求 G 整除 64:
    # 每个 kg 占 G 个 16 行格子, 只有 G | 64 时这 G 个格子才不横跨页边界,
    # 一个 kg 才能继续用一条 (lane, g, row16) 的 DMA 描述完。
    tl.static_assert(
        USCALE_ROWS_PER_PAGE_LANE % GROUPS_PER_WEIGHT_BLOCK == 0,
        "每个 K-group 段必须整除页内行数 (G | 64), 否则 kg 会横跨 WUS 页边界",
    )

    core_id = tl.program_id(axis=0)
    n_per_core = N // CORE_NUM
    total_m_blocks = tl.cdiv(M, BLOCK_M)
    total_n_blocks = tl.cdiv(n_per_core, BLOCK_N)
    total_k_blocks = tl.cdiv(K, BLOCK_K)
    total_k_groups = tl.cdiv(K, UGROUP)
    # act scale 的 K-group 维按 BLOCK_K 对齐做 padding: 这样最后一个 weight
    # block 读满 G 个 group 时也落在分配范围内(读到 padding 值), 越界部分靠
    # 下面的 mask 置零。若改用 boundary_check, 它在硬件上是裁 tile 尺寸而非
    # 补零, 读回来的 tensor 形状会和 mask 对不上。
    padded_k_groups = total_k_blocks * GROUPS_PER_WEIGHT_BLOCK

    # 三个 ptr_list 自身位于 GDG；表项分别给出本 core 的只读 weight LDG、
    # 只读 original-UScale LDG 和可写 fused-UScale arena 的基地址。
    packed_weight_addr = tl.load(packed_weight_ptr_list + core_id)
    packed_weight_base = packed_weight_addr.to(
        tl.pointer_type(tl.float8e4nv)
    )
    origin_uscale_addr = tl.load(origin_uscale_ptr_list + core_id)
    origin_uscale_base = origin_uscale_addr.to(
        tl.pointer_type(tl.bfloat16)
    )
    fused_uscale_addr = tl.load(fused_uscale_ptr_list + core_id)
    fused_uscale_base = fused_uscale_addr.to(
        tl.pointer_type(tl.bfloat16)
    )

    activation_template = tl.make_block_ptr(
        base=activation_fp8_ptr,
        shape=(M, K),
        strides=(K, 1),
        offsets=(0, 0),
        block_shape=(BLOCK_M, BLOCK_K),
        order=(1, 0),
    )
    output_template = tl.make_block_ptr(
        base=output_ptr,
        shape=(M, CORE_NUM, n_per_core),
        strides=(N, n_per_core, 1),
        offsets=(0, core_id, 0),
        block_shape=(BLOCK_M, 1, BLOCK_N),
        order=(2, 1, 0),
    )

    total_weight_blocks = total_n_blocks * total_k_blocks

    # BLOCK_M 固定为 1，但 M 是任意运行时维度。每一行必须先完成自己的
    # fused-UScale 写回和 GEMM，才能让下一行安全复用同一块 arena。
    for m_block in range(total_m_blocks):
        m_start = m_block * BLOCK_M

        # 每个 weight block 的 fused UScale 按 kg 分次读-乘-写。
        # What: 一次覆盖 (lane, g, row16) = (8, G, 16), 每个 kg 只发
        #   2 条 LD + 1 条 VP + 1 条 ST, 而不是按 (lane, group) 循环 8*G 轮。
        # Why: 一条 VP 算 128 个元素只要 4 拍却占 73 cy, 代价几乎只由指令条数
        #   决定。逐 segment 版本在 M=2/K=1024/N=128 下 128 个 segment 吃掉
        #   wall 87,985 cy(LD 30,961 + ST 19,706), 而真正的 MAC 只有 265 cy。
        # Assumption: origin/arena 页与 act scale 都能用同一套
        #   (lane, g, row16) 索引表达且 stride 递减 —— 页是
        #   (1024, 16, 1), act scale 沿 g 变、由硬件在 row16 方向广播。
        # Not covered: 仍要求 G 整除 64 (见上面的 static_assert), 即单个 kg 的
        #   scale 段不横跨 WUS 页边界; 页内 padding 不写, 由 arena 的 inout
        #   语义保留原值。
        for block_idx in range(total_weight_blocks):
            n_block = block_idx // total_k_blocks
            k_block = block_idx % total_k_blocks
            global_n_start = core_id * n_per_core + n_block * BLOCK_N
            first_k_group = k_block * GROUPS_PER_WEIGHT_BLOCK

            # 页里每个 lane 的 W 轴是 (kg, g) 两级: kg 是 128 通道的
            # super-group, g 是 K quant group, 每格 16 个连续输出通道。
            # 按 kg 拆开处理, 好处有两个:
            #   1. tile 保持 (lane, g, row16) = (8, G, 16), C=16 —— 与页内
            #      真实的连续性一致; 若把 g 和 row16 合成 C=G*16 交给 DMA,
            #      描述符会退化成一堆小传输(实测同形状 LD 指令 31 -> 157,
            #      CT 1,017 -> 3,889, wall 4,968 -> 23,301)。
            #   2. act scale 只随 g 变, 每个 kg 用的是同一份 [1,1,G,1],
            #      直接做 C 方向广播即可; 若改成沿 W 平铺, reshape 出来的
            #      视图不 compact, 会被 "VP matrix C-broadcast requires a
            #      proven compact SrcB view" 拒掉。
            # BLOCK_N = 128 时该循环退化成 1 次, 零代价。
            for super_group in tl.static_range(N_SUPER_GROUPS):
                # kg 拆成 (页号, 页内起始格子); 第 1 轴取 S*8 长后
                # 索引 = page*8 + lane, 配 stride 1024 即「跨页 + 页内 lane」。
                page = super_group // KG_PER_PAGE
                row_start = (super_group % KG_PER_PAGE) * GROUPS_PER_WEIGHT_BLOCK
                original_uscale = tl.load(
                    tl.make_block_ptr(
                        base=origin_uscale_base,
                        shape=(total_weight_blocks,
                               USCALE_PAGES * USCALE_LANES,
                               USCALE_ROWS_PER_PAGE_LANE,
                               USCALE_ROW_GRANULE),
                        strides=(USCALE_ELEMS_PER_BLOCK,
                                 USCALE_LANE_STRIDE_BF16,
                                 USCALE_ROW_GRANULE, 1),
                        offsets=(block_idx, page * USCALE_LANES, row_start, 0),
                        block_shape=(1, USCALE_LANES,
                                     GROUPS_PER_WEIGHT_BLOCK,
                                     USCALE_ROW_GRANULE),
                        order=(3, 2, 1, 0),
                    ),
                    memory_type="weight",
                )
                # act scale ABI 就是算法侧原本的 per-128 形状 [M, K/UGROUP],
                # 不需要按 WL1 lane 重排。读成 [1,1,G,1] 后由硬件沿 16 个
                # 连续通道做 C 广播。
                act_narrow = tl.load(
                    tl.make_block_ptr(
                        base=activation_scale_ptr,
                        shape=(M, 1, padded_k_groups, 1),
                        strides=(padded_k_groups, padded_k_groups, 1, 1),
                        offsets=(m_start, 0, first_k_group, 0),
                        block_shape=(1, 1, GROUPS_PER_WEIGHT_BLOCK, 1),
                        order=(3, 2, 1, 0),
                    ),
                )
                # K 是 BLOCK_K 整数倍时每个 block 的 G 个 K-group 全部有效;
                # 否则尾部 group 不存在, 必须显式置零 —— 同一块 arena 会被
                # 后续 M 行复用, 不置零会残留上一行的 fused scale。
                # K_ALIGNED 默认 False(带 mask), 只有调用方执行了
                # resolve_constants 并确认 K 对齐才升级为 True —— 默认值必须
                # 在保守的那一侧, 否则跳过 resolve_constants 的调用方会静默
                # 丢掉 mask。
                #
                # 为什么 mask 写成这个样子:
                #   - boundary_check 只防越界访问, 它在硬件上是裁 tile 尺寸
                #     而非补零, 被裁掉的部分在 L2 里留的是未初始化数据, 所以
                #     act scale 的 K-group 维要按 BLOCK_K 对齐 padding;
                #   - tensor 条件的 tl.where 编译不了(linalg.generic 无法
                #     legalize, issue #196), 只能用纯 f32 算术凑
                #     clamp(valid-g, 0, 1);
                #   - 不能用 scf.if 分快慢路径 —— 两分支 ST 条数不同会让
                #     InjectSync 的 ST->VP credit 算不平(issue #197)。
                if K_ALIGNED:
                    fused_uscale = original_uscale * act_narrow
                else:
                    group_ids = tl.arange(
                        0, GROUPS_PER_WEIGHT_BLOCK
                    ).to(tl.float32)[None, None, :, None]
                    valid_groups = (
                        total_k_groups - first_k_group
                    ).to(tl.float32)
                    group_mask = tl.minimum(
                        tl.maximum(valid_groups - group_ids, 0.0), 1.0)
                    fused_uscale = (
                        original_uscale.to(tl.float32)
                        * act_narrow.to(tl.float32) * group_mask
                    ).to(tl.bfloat16)
                # 方案二: 写入独立 arena 的对应 page, 不再碰 packed weight。
                # arena 与 origin_uscale 同序同布局, 所以与上面的 origin load
                # 共用同一个 block_ptr 形状, 只换 base。ST 与后面 PE 读同一页
                # 的 RAW 依赖由编译器为该 slab 单独登记的同步资源建立。
                tl.store(
                    tl.make_block_ptr(
                        base=fused_uscale_base,
                        shape=(total_weight_blocks,
                               USCALE_PAGES * USCALE_LANES,
                               USCALE_ROWS_PER_PAGE_LANE,
                               USCALE_ROW_GRANULE),
                        strides=(USCALE_ELEMS_PER_BLOCK,
                                 USCALE_LANE_STRIDE_BF16,
                                 USCALE_ROW_GRANULE, 1),
                        offsets=(block_idx, page * USCALE_LANES, row_start, 0),
                        block_shape=(1, USCALE_LANES,
                                     GROUPS_PER_WEIGHT_BLOCK,
                                     USCALE_ROW_GRANULE),
                        order=(3, 2, 1, 0),
                    ),
                    fused_uscale,
                    memory_type="weight",
                )

        # 当前行的 scale 写完后走标准 blocked GEMM。weight load 用 uscale=
        # 把本 tile 绑定到 arena 中的对应 page；tl.dot 本身不新增 scale 参数。
        for n_block in range(total_n_blocks):
            n_start = n_block * BLOCK_N
            accumulator = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

            for k_block in range(total_k_blocks):
                k_start = k_block * BLOCK_K
                block_idx = n_block * total_k_blocks + k_block

                activation = tl.load(
                    tl.advance(activation_template, (m_start, k_start)),
                    boundary_check=(0, 1),
                    padding_option="zero",
                )
                weight_block_byte_offset = block_idx * WEIGHT_BYTES_PER_BLOCK
                weight = tl.load(
                    tl.make_block_ptr(
                        base=packed_weight_base + weight_block_byte_offset,
                        shape=(BLOCK_N, BLOCK_K),
                        strides=(BLOCK_K, 1),
                        offsets=(0, 0),
                        block_shape=(BLOCK_N, BLOCK_K),
                        order=(1, 0),
                    ),
                    memory_type="weight",
                    ugroup=UGROUP,
                    # 方案二: 本 weight tile 的 UScale 来自 arena 里属于该 block
                    # 的 S 个连续 16 KiB page。这里给的是**第一页**的起始指针,
                    # 编译器据此推导 USaddr —— 硬件只需要起点, 后续页由地址
                    # 生成器按 tk/tc 计数器自己走过去 (VCS job 23a02ed4fcc0 实证)。
                    uscale=fused_uscale_base
                    + block_idx * USCALE_ELEMS_PER_BLOCK,
                )
                accumulator += tl.dot(
                    activation,
                    tl.trans(weight),
                    out_dtype=tl.float32,
                )

            tl.store(
                tl.advance(output_template, (m_start, 0, n_start)),
                tl.expand_dims(accumulator.to(tl.bfloat16), 1),
                boundary_check=(0, 2),
            )


signature = {
    "activation_fp8_ptr": "*fp8e4nv",
    "activation_scale_ptr": "*bf16",
    "packed_weight_ptr_list": "*i64",
    "origin_uscale_ptr_list": "*i64",
    "fused_uscale_ptr_list": "*i64",
    "output_ptr": "*bf16",
    "M": "i32",
    "K": "i32",
    "N": "i32",
}

constants = {
    "CORE_NUM": 1,
    "BLOCK_M": 1,
    "BLOCK_K": 1024,
    "BLOCK_N": 256,
    "UGROUP": 128,
    "USCALE_PAGES": 1,
    # 默认取保守的 False(带尾块 mask)。resolve_constants 只在确认 K 对齐后才
    # 把它升级成 True。
    # CONTRACT: 不是所有调用方都会执行 resolve_constants —— GEMM suite 的
    # run_all_tests.sh 先用本 constants 编译一份 .zeushigh.mlir, 再把这份 IR
    # 连同各 case 的 --dynamic 交给 sim_test.py, 此时 resolve_constants 不会被
    # 调用。默认 True 会让这类调用方在 K 非 BLOCK_K 整数倍时静默丢掉尾块 mask,
    # arena 的无效 group 残留上一行的 fused scale。默认 False 在同样情况下只是
    # 多付 mask 的代价, 结果依然正确。
    "K_ALIGNED": False,
}


def resolve_constants(dynamic, constants):
    """按运行时 K 选择是否需要尾块 mask。

    K 是 BLOCK_K 整数倍时每个 weight block 都读满 G 个 K-group, 不需要 mask;
    否则最后一个 block 有尾部 group 要置零。两条路径在编译期二选一, 对齐场景
    因此不付 mask 的代价。

    CONTRACT: `dynamic` 里没有 K 时必须保守地判为"不对齐"。zeus_compile.py 从
    环境变量 ZEUS_SIM_DYNAMIC 取 dynamic, GEMM suite 的 Phase 1 在不设该变量的
    情况下先编译一份通用 IR, 再把它连同各 case 的 --dynamic 交给 sim_test.py。
    此时若拿 BLOCK_K 当 K 的缺省值, 就会算出 K_ALIGNED=True 并静默丢掉 mask,
    而那份 IR 随后会被 K 非 BLOCK_K 整数倍的 case 使用 —— arena 的无效 group
    会残留上一行的 fused scale。缺失信息必须落到带 mask 的安全侧。
    """
    block_k = int(constants["BLOCK_K"])
    k_size = dynamic.get("K")
    constants["K_ALIGNED"] = (
        k_size is not None and int(k_size) % block_k == 0
    )
    return constants
