02 / KERNEL BREAKDOWN

四项计算，三个执行阶段

Zeus · 16 rank / 32 core

当前测量流程：本地 BF16 token → Router+Shared → FP8 AllGather → Routed → Reduce。Router 与 Shared 在同一次 launch 中执行，以下按三个实际入口统计，不能再独立添加 Shared 时间。

01 · 本地路由与共享专家

Router + Shared

每个 rank 只处理自己拥有的 token。Router 使用 calibrated sigmoid 和带 bias 的 Top-K；Shared 使用完整 I2048 BF16 权重，两个 core 各 I1024。两部分在同一 kernel 中融合调度。

关注：本地 token 分区与融合重叠。Shared 保持 BF16 输入，发给 Routed 的 hidden 才转换为 FP8。
02 · 全 batch 稀疏专家

Routed

读取 FP8 transport 与显式 parity sidecar，按真实路由进行全 batch M1 / M2 / M4 合组，执行 Gate / Up、SiLU 与 Down。BS>32 使用每核私有 FP8 DRAM staging。

关注：跨窗口权重复用、尾组与专家分布；planning、staging、scatter 均计入耗时。
03 · 本地加权归并

Reduce

在正确的 owner token 区间注入 Shared，按原 slot 顺序累加有效 Routed 输出与路由权重，保留 FP32 累加和最终 BF16 舍入。

关注：owner 边界、有效行访问与 VP 加权开销。跨卡 Reduce-Scatter 不在计时窗口内。

BS16–128 使用统一入口，batch 是编译期常量。此次显式启用 PR730 的 parity_masks；SGLang 默认 IDs 与本次实验配置分开记录。M4 是一次 PE 的行数，不是合组范围上限。

口径：总 BS × 400,000,000 ÷ 该阶段 42 层平均 cycles ÷ 4。各层先取该阶段最慢 rank（Router 取最慢 owner），累加 42 层，再对 49 个采样点取平均时间。分子只计模型输入 token，不乘 Top-K 或层数；Shared 也按四卡归一化。

曲线走平表示增加 batch 后该阶段的单位卡处理速率不再明显提高；向下表示时间增长超过 token 数增长。可勾选曲线或点「只看」检查；交互图默认放大纵轴范围，突出变化趋势；可勾选「纵轴从 0 开始」比较绝对比例。下载图保留从零开始的完整阶段曲线。

03 / SAMPLING

49 个点是怎样组成的？

896条不同请求
→
7 × 128批次 × 每批请求数
→
7个固定 decode 位置
→
49个采样点 / batch 档位
一个采样点
一批请求在一个 decode 位置的真实逐层输入，例如 train00 / step017；每个点均重放全部 42 层 MoE。不是 49 批请求，也不是连续执行 49 个 step。
保留的 decode 位置
017、033、049、065、081、097、113。索引从第一个 decode forward 的 0 开始；step001 已从双方全部 batch 和数据划分中排除。
batch 如何对齐
总 BS16–128，间隔 8，共 15 档。每层 BS16 取该层 BS128 父输入的前 16 行，BS32 取前 32 行；H200 与 Zeus 用 hidden hash 核对。每层独立重放，不宣称运行过相应小 batch 的整模轨迹。
统计与选择
同一 batch 的 49 个点按总 token / 总时间汇总。train 3 批、validation 2 批、test 2 批；只用 train 选择 batch，随后报告 holdout。同一请求的多个 step 存在关联，不视作 49 个独立同分布样本。

04 / MEASUREMENT & VALIDATION

测量边界与验证记录

Zeus TP4 × EP4

4 card / 16 rank / 32 core，400 MHz。每个 launch 取最慢 core；每层先取最慢 owner 的 Router+Shared，再加最慢 rank 的 Routed + Reduce，最后累加 42 层。gather 是依赖边界，真实通信耗时未计入。

cycles = Σ层 [max_owner(Router+Shared) + max_rank(Routed + Reduce)]
tokens/s/card = 总 BS × 400,000,000 ÷ cycles ÷ 4

H200 MoE TP1 × EP4

4 张 H200 NVL，每卡 72 个完整 Routed 专家；独立 FP8 Shared 跨四卡 TP4。各层先取每轮重复均值，再取轮次中位数，取最慢 EP 后累加 42 层。

tokens/s/card = 总 BS × 1,000 ÷ ms ÷ 4

激活采集拓扑为 TP4/EP1，与执行拓扑分开记录。当前 Zeus 统计纳入 493,920 个时序 case；H200 保留 2,940 个 rank case / 123,480 个层卡点。Zeus 使用捕获的 H1 输出和 CPU collective double，不计 H1、真实通信、host/JIT，也没有新增 VCS/RTL 或整模型性能结论。

查看时序资格、数值验证与解析误差

完整 49 点 × 15 档 × 42 层 × 16 rank：493,920 个时序 case 全部审计完成。并发上限 192，实际峰值 192；宿主耗时 19.34 小时。宿主耗时包含磁盘空间保护触发的暂停，不是设备计算延迟。原始输入、权重身份与旧 Notes 测量逐 case 核对，H200 数据保持原样。
